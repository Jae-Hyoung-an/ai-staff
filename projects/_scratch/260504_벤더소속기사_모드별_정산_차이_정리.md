# 260504 벤더 소속 기사 모드별 정산 차이 정리

> 참고 문서: M캐시 지급 흐름 정리, 벤더 정책/기능명세 최신 반영본
> 작성일: 2026-05-04

---

## 1) 비교 대상

- 케이스 A: 벤더 소속 기사가 **벤더 모드(DP-S)** 로 오더 수행
- 케이스 B: 벤더 소속 기사가 **벤더 모드가 아닌 상태(DP-F/DP-FA)** 로 오더 수행

---

## 2) 한눈에 보는 차이

| 구분 | 케이스 A: 벤더 모드(DP-S) | 케이스 B: 벤더 모드 아님(DP-F/DP-FA) |
|------|-----------------------------|---------------------------------------|
| 정산 경로 | 본사 → 벤더(주간 일괄) → 기사 | 본사 → 기사(M캐시 즉시) |
| 기사 체감 지급 시점 | 벤더 주간 정산 후 지급 | 배송 완료 직후 |
| 기사 앱 캐시 | V캐시(정산 예정 금액 표시, 출금 불가) | M캐시(실입금, 출금 가능) |
| 소득세 처리 | 기사 지급액 산정 시 차감 + 벤더 정산에 가산 + 벤더 신고/납부 | 기존 정책 동일(본사 즉시 정산 체계 기준으로 처리) |
| 고용/산재 처리 | 기사부담/사업주부담 분리 계산·차감, 본사 신고 | 기존 정책 동일(기사부담/사업주부담 분리 계산·차감, 본사 신고) |
| 배차 포기 증액 | 미적용(0원) | 기존 정책 적용(필요 시 기존 룰 따름) |
| 운영 책임 중심 | 벤더 정산/기사 지급 관리 필요 | 본사 정산 시스템이 직접 처리 |

---

## 3) 흐름 비교

### A. 벤더 모드(DP-S)

```text
오더 수행 완료
  → 수행 실적 집계
  → 소득세/보험 등 정산 항목 계산
  → 본사 → 벤더 주간 일괄 정산(기사몫 포함)
  → 벤더 → 기사 지급
  → 소득세는 벤더가 신고/납부
```

### B. 벤더 모드 아님(DP-F/DP-FA)

```text
오더 수행 완료
  → 기존 즉시 정산 로직 적용
  → 본사 → 기사 M캐시 실시간 입금
  → 소득세/보험 등은 기존 정책 체계로 처리
```

---

## 4) 실무 해석 포인트

- 같은 `벤더 소속 기사`라도 **수행 모드**에 따라 정산 경로가 달라진다.
- DP-S는 `주간 일괄 정산`, DP-F/DP-FA는 `즉시 정산`으로 분리 이해해야 한다.
- 재무/정산 커뮤니케이션에서 가장 중요한 문구는 다음 2개다.
  - `DP-S는 본사→기사 즉시 지급 없음`
  - `DP-S 소득세는 본사 미신고, 벤더 신고/납부`

---

## 5) 운영/개발 체크리스트

| 영역 | 체크 항목 |
|------|-----------|
| 운영 | 벤더/기사 안내 시 DP-S와 DP-F/DP-FA 정산 시점 차이를 반드시 분리 안내 |
| 정산 | 주간 정산서에서 소득세 차감분이 벤더 정산 가산 항목으로 반영되는지 확인 |
| 개발 | 모드별 정산 분기(DP-S vs DP-F/DP-FA)에서 지급 경로/캐시 타입(V캐시/M캐시)이 올바르게 분리되는지 테스트 |
