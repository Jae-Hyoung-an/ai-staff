# 01. 체크리스트 — 배포 후 기존 벤더존 지점 설정 전환

> 항목 형식: `[ ] ID. 작업 — 담당 · 선행 · 완료기준 · 기록 · 근거`
> ID 체계: **P**(사전, D-7~D-1) · **D**(배포 당일 세팅, 지점별 반복) · **M**(D+1 마이그레이션 동반 대조) · **V**(검증) · **W**(모니터링 D+0~D+3) · **R**(되돌리기·공백 관리) · **Q**(개발 확인 질문)
> 전제 A·B·C는 `00_index.md`를 따른다. **전제 B(전량 재입력)가 기본이며, `Q-`에서 개발 이관이 확인된 항목은 해당 `D-` 항목을 "확인만"으로 바꾼다.**

## 0. 한눈에 보기 — 지점 하나가 "새 원가로 배차되는 상태"까지

```
[사전 P]  요금제 선행 세팅(판가·원가 축)  ·  권역 초안  ·  현황 스냅샷  ·  벤더/기사/상점 정리
     ↓ 배포 (구 화면 사라짐)
[D-1~2]   배포 확인 → 지점 운영방식 벤더존 · 탭 노출
[D-3~4]   03 탭: 영업존 권역 1개 그리기 ─┬─ 벤더 배송권역 1개 그리기   ← 두 섹션 따로 저장, 사유 필수
[D-5~6]   02 영업존 연결 → 영업 존 요금제에서 영업존 추가           ← 판가 축 완결
[D-7]     09 정책: 지점 담기 + 권역별 요금제 지정 + 보상·물량        ← 원가 축 절반
[D-8]     10 세트 분배: 벤더 추가 + 세트 수 저장 (= 벤더 연결, 기사 지점 이동)  ← 원가 축 완결 · 배차 시작
[D-9~11]  11 벤더 미연결 0 · 기사 관리지점 대조 · 상점 관제지점·영업 존 요금제
[D-12]    지점 블록 완료 판정
     ↓
[M]  D+1 개발 마이그레이션 전후 대조   →   [V] 테스트 배차 4분류   →   [W] D+0~D+3 지표
```

## 1. P — 사전 준비 (D-7 ~ D-1, 기존 시스템에서)

### 1.1 현황 실측
- [ ] **P-1. 전환 대상 스냅샷 확정** — PO · 선행 없음 · 완료기준: 벤더존 지점마다 ZONE명 · ZONE 권역정책명 · 세트분배(벤더별 세트 수) · 벤더 목록(상태) · 벤더별 기사 수 · 관제 상점 수 · 상점 통합 요금제 지정 현황을 한 표로 확보 · 기록: `02_지점별_실행표.md` 상단 표 · 근거: R2 §2.1(7/29 실측 6 ZONE·9 정책·26 벤더·6 세트분배, 실운영 3·8), 9/3 위클리 액션 "세팅 업무 목록 정리"
- [ ] **P-2. 지점별 운영용 세일즈 권역 수 조사** — 권역 담당 · P-1 · 완료기준: 벤더존 지점 중 운영용 세일즈 권역이 2개 이상인 곳과, 그중 실제로 판가를 나눠야 하는 곳 목록. 나눠야 하면 **지점을 추가로 만들어야 한다**(영업존 ↔ 지점 1:1, 지점당 영업존 권역 1개) · 기록: 지점 추가 필요 여부 · 근거: 14 §3.1 조사 ①②③, 02 EZ-2, 9/3 위클리 결정 6
- [ ] **P-3. 벤더 배송권역 ↔ 지점 대응 확정** — 벤더 담당 + PO · P-1 · 완료기준: 지점당 벤더 배송권역 1개 원칙에서, 현재 한 ZONE에 여러 벤더가 있고 벤더별로 권역을 다르게 그려야 하는지 판단. 다르게 그리려면 **배송권역용 지점을 추가 생성**해야 한다 · 기록: 추가 지점 수(M-2 규모) · 근거: 14 M-2, 00 §3.2, 8/27 회의 "지점 분리 vs 통합" · → `Q-5`
- [ ] **P-4. 벤더별 소속 기사 명단 · 현재 관리지점 스냅샷** — 벤더 담당 · P-1 · 완료기준: 벤더 → 기사 → 현재 관리지점 CSV. 배포 후 자동 동기화 결과와 대조하는 기준선 · 근거: 11 VEN-6, 10 SET-9, 14 M-3
- [ ] **P-5. 영업 기준 권역(기존) 중첩 실측** — 권역 담당 · 선행 없음 · 완료기준: 벤더존 지점의 기존 영업 기준 권역끼리 겹치는 곳 목록. 영업존 권역은 **새로 그리므로** 이 결과는 P-6 초안 설계의 참고값 · 근거: 14 M-4 "중첩 해소는 영업 축만", 04-1 §4 "영업기준 픽업지는 영업존 권역과 별개"

### 1.2 권역 초안
- [ ] **P-6. 지점별 영업존 권역 초안** — 권역 담당 + 영업 · P-2 · P-5 · 완료기준: 지점마다 폴리곤 1개(H3), **다른 벤더존 지점의 영업존 권역과 겹치지 않음**, OD·스타벅스 등 특수 권역 제외한 순수 영업·요금제 판단용 · 기록: 초안 파일/지도 링크 · 근거: 00 §3.1 중첩 불가, 02 EZ-5, 03 PT-4, 9/3 위클리 결정 8, 9/8 논의(H3)
- [ ] **P-7. 지점별 벤더 배송권역 초안** — 벤더 담당 + 라스트마일 · P-3 · 완료기준: 지점마다 폴리곤 1개, **이웃 지점까지 의도적으로 겹치게**(징검다리), 이웃 권역 사이 빈 지역(→ 그 오더는 폴백·프렌즈) 최소화 · 기록: 초안 · 근거: 00 §3.2 중첩 허용, 03 PT-5, 09 POL-8, 01 §3.4(겹치면 프렌즈 원가 하락 — 의도된 부작용)
- [ ] **P-8. 04 지점 권역 관리(조회)로 기존 7종 권역 확인** — 권역 담당 · 배포 후에만 가능하면 D-당일로 이동 · 완료기준: 픽업지·배송지·영업기준 픽업지·영업기준 배송지·제한 권역이 그대로 남아 있고, 신규 2종은 `미등록` 상태 · 근거: 04-1 §4, 00 §5.2

### 1.3 벤더 · 기사 정리
- [ ] **P-9. 벤더 상태 정리** — 벤더 담당 · P-1 · 완료기준: 해지·QA 잔여 벤더는 `해지`로, 운영할 벤더는 `운영중` + 벤더장(VO) 지정 완료. **운영중이 아니면 세트 분배 후보에 나오지 않는다** · 근거: 10 SET-5, 11 VEN-4·VEN-8, R2 §2.1(26 중 8 실운영)
- [ ] **P-10. 미연결로 남길 벤더 결정** — 벤더 담당 · P-9 · 완료기준: 배포 후에도 의도적으로 권역에 붙이지 않을 벤더 목록(그 기사는 배차 후보 제외, 운영이 지정한 지점에 수동 배치) · 근거: 11 VEN-2·VEN-7, 09 POL-13
- [ ] **P-11. 벤더 사전 고지** — PO + 벤더 담당 · P-7 · 완료기준: 벤더장에게 ① 권역이 새로 그려진다 ② 기사앱 소속 표기가 바뀔 수 있다(F-8) ③ 권역 외·회귀 오더는 `수락 전 취소`에서 빠지고 컬럼이 추가된다(VP-1·VP-3) ④ 기사 지점 이동은 별도 안내 없음(SET-9) 을 전달 · 근거: 09 S-7 "문서 밖의 운영 약속", 10 S-3, 12 §4.2

### 1.4 요금제 선행 세팅 (핀테크 + PO) — 배포 후 신 메뉴에서 하는 작업이면 D-0 앞단으로 이동
- [ ] **P-12. 판가 축 요금 상품 준비** — 요금제 · 영업기준 협의 완료 · 완료기준: 지점별 **판가 요금** 등록 → (필요 시) **판가 할증 · 판가 프로모션** → **영업 존 요금제**(판가 요금 1 + 할증 N + 프로모션 N) 생성, 영업기준표 검증 통과 · 기록: 영업 존 요금제 코드 · 근거: 요금제 관리 PRD §3.3·§4, 02 §4.3 섹션 3 · → 기존 통합 요금제 승계 여부 `Q-6`
- [ ] **P-13. 원가 축 요금 상품 준비** — 요금제 · 벤더 원가 협의 완료 · 완료기준: **원가 요금**(라이더비·관제비·관리비·픽업비·완료비 + 거리 구간) → **원가 할증**(기상·시간대·폴리곤·특수 + **권역 외 할증 정액**) → **벤더 배송권역 요금제**(원가 요금 1 + 원가 할증 N) 생성 · 기록: **요금제 코드 + UUID** (09 정책에서 지정할 때 필요, 이름 중복 가능하므로 코드 병기) · 근거: 요금제 관리 PRD §3.3·§4.4~4.6, 09 §3-1, 9/9 벤더셋 스펙 공유 "요금제 코드 기반 검색 병행"

- [ ] **P-15. 원가 금액이 붙은 기존 판가 할증 식별** — 요금제 · P-1 · 완료기준: 판가 0원·원가만 있는 할증 목록(동대문 5건 등). 새 구조에서는 **원가 할증으로 복제 생성 후** 판가 쪽 종료 — 순서를 뒤집으면 원가 공백 · 근거: R2 M6·§2.4, RK4

- [ ] **P-17. 원가 ↔ 판가 마진 수기 검토** — 마켓플레이스실 · P-12 · P-13 · 완료기준: 영업존 권역과 벤더 배송권역이 N:M이라 시스템이 마진을 검증하지 않으므로, 겹치는 구간의 판가·원가 역전 여부를 표로 확인 · 근거: 00 §3.3, 09 §3-1 "마켓플레이스실이 수기로 확인", 요금제 관리 PRD "원가는 시스템 검증을 수행하지 않는다"

## 6. R — 되돌리기 · 공백 관리

- [ ] **R-1. 원가 공백 금지 순서** — 모든 단계에서 **새 것을 먼저 만들고(복제·연결) → 검증 → 옛 것 종료**. 반대로 하면 그 사이 오더의 벤더 원가가 사라진다 · 근거: R2 §2.4 M6, RK4, B존 전환 SOP "3-3과 3-5는 같은 배치"
- [ ] **R-2. 발효 시각 통일** — 벤더 이동·정책 변경처럼 두 화면을 거치는 변경은 **예약 저장으로 같은 발효 일시**를 준다. 그 사이 벤더 기사는 어느 권역의 후보도 아니다 · 근거: 10 S-2
- [ ] **R-3. 되돌릴 수 없는 것 인지** — 배포 후 접수된 오더의 확정 원가·정산은 되돌릴 수 없다. 배포 후 문제가 발견되면 **설정을 고쳐 이후 오더부터 바로잡고, 이미 나간 금액은 정산 보정**으로 처리한다는 원칙을 정산팀과 사전 합의 · 근거: 14 §4.2, 00 §4.3
- [ ] **R-4. 정책 멈추기 방법** — `비활성화` 버튼이 없다. 멈추려면 권역 연결을 비운 버전을 저장한다(그 권역 벤더 연결 자동 해제 → 확인 모달). 진행 오더는 접수 시점 기준으로 완료 · 근거: 09 POL-11·POL-16, 09 S-5
- [ ] **R-5. 의지하는 서버가 답하지 않을 때** — 권역 판정·원가를 못 받으면 배차를 멈추지 않고 폴백 원가로 진행 + 경보. 폴백 오더는 실적·정산 동일, 추적에서만 구분 · 근거: 14 §4.3, 01 §6.1
