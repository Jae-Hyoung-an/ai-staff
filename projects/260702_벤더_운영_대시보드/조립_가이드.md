# 벤더 운영 대시보드 — Metabase 조립 가이드

> 데이터: Snowflake (Metabase `database_id=12`).
> **스코프 (2종)**: 수요·배송퀄리티 = **권역 접수(관제지점) 기준** = 해당 권역에 접수된 총 오더(수행주체 무관) / 공급(C1·C3) = **벤더 기준**(세트원장·벤더 기사).
> 권역 연결: `ORDERS.MONITORING_PARTNER_ID = ZONES.EXTERNAL_PARTNER_ID`. 필터 미입력 시 전체 권역.
> 검증일: 2026-07-03. 운영 존 예: `동대문 1`(EXTERNAL_PARTNER_ID=4563, 7/2 접수 513건).

## 3. 지표 정의 (확정본)

- **오더 시간 기준 = `CREATED_AT`** (2026-07-09 확정): `CREATED_AT` = 상점이 오더를 넣은 시점(실제 수요·상점 체감 기준). `SUBMITTED_AT` = 픽업요청 시점까지 배정 실패 시 오더가 '접수(전체공개)' 상태로 전환된 시점 — AI 배차(생성 직후부터 제안 지속)가 옵티멀하게 배정하지 못했다는 신호이므로 **수요/SLA 시간축으로 사용 금지**. 모든 수요·배송퀄리티 카드의 버킷·기간필터는 `CREATED_AT` 기준.
- **권역 스코핑(수요·배송퀄리티)**: `ORDERS.MONITORING_PARTNER_ID = ZONES.EXTERNAL_PARTNER_ID`(활성 존, 테스트존 제외). 즉 **권역의 총 오더** — 수행주체(벤더/프렌즈)와 무관하게 카운트. (KPI 총물량이 운영 레퍼런스와 일치)
- **수행주체 분류(B3·B4)**: 벤더세트 = 수행기사가 현재 벤더세트 소속(`AGENT_ID→VENDOR_AGENTS`) / 프렌즈 = 그 외 `IS_VROONG_FRIENDS_ORDER` / 기타·미배차 = 나머지
- **물량타입** (판별 순서 위→아래): **G4 = 영업구분(`SALES_TYPE`) `직영센터`** (최우선) / OD = 관리구분(`MANAGEMENT_TYPE`) `요기요OD` / 법인 = `메쉬프라임` / 로컬 = `로컬세일즈` / 기타 = 나머지(리셀러 등)
- **40분 완료 (SLA)**: `DATEDIFF('second', CREATED_AT, DELIVERED_AT) <= 2400` (완료건 분모) — 오더 생성→완료, 상점 체감 기준. ⚠️ `COMPLETE_TIME` 컬럼은 `SUBMITTED_AT`→`DELIVERED_AT` 소요시간이라 사용하지 않음 (동대문 6/29~7/5 실측: 생성 기준 90.9% vs 접수 기준 95.6%). C3는 배차→완료(`DISPATCHED_AT`→`COMPLETED_AT`) 기준
- **취소**: 수요/KPI = `ORDER_STATUS='취소'` / C3 = 세트원장 `DISPATCH_STATUS='30'`
- **거절률 (C3, PRD SD2-5/6)**: 거절건(적극거절 `OUTCOME=20` + 만료 `30` + 수락후취소 `60`) / 완료오더(`DISPATCH_STATUS='20'`)
- **달성세트수**: 완료 슬롯 = `(WEEK_ANCHOR_DATE, DAY_OF_WEEK, SLOT_INDEX)` distinct 중 완료 발생분
- **프렌즈/벤더**: 위 "수행주체 분류" 기준 (B3·B4). 7/2 동대문 예시 = 총 513 → 벤더세트 408 / 프렌즈 102 / 미배차 3
- **온듀티**: `audit_events`(VENDOR_AGENT) 이벤트 리플레이. SET=벤더(DP-S), FRIENDS=프렌즈전환(DP-F)
- **시리즈 표준**: 물량타입 분해 카드는 **법인/OD/G4 + 전체** 4시리즈로 통일 (로컬·기타는 분모가 작아 %지표 왜곡 → 시리즈 제외, '전체'에는 포함)
- **수익성 (D, 완료건만)**: 판가 = `STORE_BILLABLE_FEE ÷ 1.1` (VAT 10% 제외, billable=base+extra) / 원가 = `AGENT_FEE + AGENT_EXTRA_FEE` (기사 지급분, VAT 미포함 금액 — 확인 완료, 그대로 사용) / CM = 판가 − 원가, CMR = ΣCM ÷ Σ판가. ⚠️ 벤더세트 실원가는 주간 세트 정산 기준이라 기사원가와 다를 수 있음 (벤더 원가 정의 논의 중, 잠정 기사원가 사용). 관리비·관제비 미포함

## 4. 보정 반영 사항

1. 한글 컬럼 별칭은 Snowflake에서 `"큰따옴표"` 필수
2. 테스트/QA 제외: 수요·배송퀄리티는 `ZONES.ZONE_NAME`에서, 공급은 `VENDORS.BUSINESS_NAME`에서 `NOT ILIKE '%QA%'/'%테스트%'/'%test%'`
3. WoW는 부분일(오늘) 제외: `PARTITIONAL_DATE < CURRENT_DATE`
4. 온듀티 댕글링 세션(종료 이벤트 없는 기사) 18시간 캡
5. (2026-07-03) 수요·배송퀄리티 스코핑을 **벤더세트 수행 기준 → 권역(관제지점) 기준**으로 변경. 상단 총물량이 권역 총량과 일치하도록. B3·B4는 수행주체 태그로 벤더/프렌즈 분리.
6. (2026-07-09) 시간 기준을 `SUBMITTED_AT` → **`CREATED_AT`** 으로 전면 변경 (수요·배송퀄리티 8개 카드). SLA도 `COMPLETE_TIME` → `CREATED_AT→DELIVERED_AT`로 교체. 사유: `CREATED_AT`이 상점 주문 시점이고 `SUBMITTED_AT`은 배정 실패 시 전체공개 전환 시점이라 상점 체감 품질과 무관.
7. (2026-07-09) 카드 개편: A2 스코어카드 → WoW 트렌드(4시리즈) / B1 취소율만 남기고 4시리즈 / B2 4시리즈 / B3 Pie → 100% 적층 트렌드 / **D 수익성 섹션 신설** (D1 판가, D2 기사원가, D3 CM). 물량타입 시리즈는 법인/OD/G4+전체로 통일.

## 6. 시간대(타임존) 검증 결과 (2026-07-03)

- 모든 타임스탬프는 올바른 instant(TIMESTAMP_LTZ). Metabase 세션이 `Asia/Seoul`이라 `DATE_TRUNC`/`HOUR`/날짜비교가 KST로 계산됨. `ORDER_NUMBER` 앞자리(KST)와 일치 확인.
- `PARTITIONAL_DATE`는 KST 날짜 기준(자정 경계 극소수 노이즈).
- 갱신 주기: `DATAMART.ORDERS`·`RAW_VENDORSET.*`는 실시간(5~15분 지연), `AGENT_WORK_STATUS`만 일 1회 배치(~04:00 KST). → 온듀티는 실시간 `audit_events` 사용이라 영향 없음.
- 세션 타임존 비의존이 필요하면 시간 추출을 `CONVERT_TIMEZONE('Asia/Seoul', 컬럼)`으로 감싸면 됨(선택 하드닝).
