## 화면 지도

```
세트 관리
└─ ZONE 권역정책 관리                    /vendor/operation-policies
   │                                     (목록 · 검색 · 총 9건)
   │
   ├─ [+ 관리정책 생성] ──────────────→  /vendor/operation-policies/add
   │                                     "ZONE 권역정책 추가"
   │                                     탭 없음 · [목록으로][저장]
   │                                     └─ [+ ZONE 추가] → ZONE 검색 모달
   │
   └─ 행 클릭 ───────────────────────→  /vendor/operation-policies/{id}
                                         "ZONE 권역정책 조회 - {정책명}"
                                         [목록으로][예약 저장][저장]
                                         │
                                         ├─ 탭1: 기본정보
                                         │        6개 섹션
                                         │        └─ [+ ZONE 추가] → ZONE 검색 모달
                                         │
                                         └─ 탭2: 변경 이력          #ChangeHistory
                                                  버전 목록
                                                  └─ [비교] → 버전 비교 모달
```

> 같은 메뉴인데 화면 제목이 3가지로 갈립니다. 목록은 **관리**, 상세는 **조회**, 생성은 **추가**입니다.
> 좌측 메뉴명은 "ZONE 권역정책 관리"이지만 breadcrumb 3단계는 화면마다 달라집니다.

## 조사 범위와 한계

### 확인한 것

- 목록 화면 전체 (검색 조건 옵션값, 컬럼, 페이지네이션, 등록 데이터 9건)
- 상세 화면 기본정보 탭 전체 (6개 섹션, 모든 필드값 — 성북 1 zone 기준)
- 상세 화면 변경 이력 탭 (컬럼, 버전 2건, 상태값)
- 버전 비교 모달 (비교 대상 항목 전체)
- 생성 화면 전체 (모든 기본값, 검증 문구, 조회 화면과의 차이)
- ZONE 검색 모달 (검색 결과 컬럼, ZONE 마스터 전체 6건)
- 셀 다중선택 → 벌크 입력 UX 동작 방식

### 확인하지 못한 것

| 항목 | 이유 | 다음에 확인할 방법 |
|------|------|-------------------|
| 저장 / 예약 저장 동작 | 운영 데이터 변경 위험으로 클릭하지 않음 | QA 환경에서 테스트 |
| 예약 저장 시 적용 시작일 입력 UI | 위와 동일 (모달인지 인라인인지 미확인) | QA 환경 |
| 활성/비활성 전환 경로 | 상세 화면 `상태` 필드가 읽기전용, 전환 UI를 못 찾음 | 개발팀 확인 필요 |
| 유효성 검증 규칙 상세 | 정상값만 입력된 상태라 에러 문구를 못 봄 | QA 환경에서 경계값 입력 |
| 정책 삭제 기능 | 화면상 삭제 버튼 없음 (ZONE 행 삭제만 존재) | 개발팀 확인 필요 |
| 권한별 화면 차이 | PO팀 계정 1개로만 조사 | RM/BTF 계정으로 재확인 |

## 핵심 데이터 모델 (화면에서 역추론)

```
OperationPolicy (관리정책)
├─ id                          : /{id} 경로 파라미터 (성북=9)
├─ name                        : 관리정책명 (필수, 유니크 추정)
├─ description                 : 정책 설명 (선택)
├─ status                      : 활성 | 비활성  ← 화면에서 읽기전용
├─ createdAt / updatedAt       : 목록의 생성일 / 마지막 수정일
├─ createdBy                   : 등록자 (상세 우상단)
│
├─ zones[]  ──────────────────→ Zone (id, name)   ※ 복수 연결 가능
│
├─ rewardCondition (보상 조건)
│  ├─ acceptanceRate           : 수락률
│  └─ successSlotCount         : 성공 슬롯 수 (= 비교화면의 "최소 목표 슬롯")
├─ rewardAmount
│  └─ perSetReward             : 세트당 보상 금액 (원)
├─ setComposition
│  └─ maxActiveRidersPerSet    : 세트당 최대 활성화 기사수
│
├─ slots[5] (슬롯 정의)
│  ├─ name                     : 자유 입력 (maxlength 50)
│  ├─ startTime / endTime      : HH:mm 입력, 비교화면은 HH:mm:ss 표기
│  └─ enabled                  : 슬롯1은 강제 true, 슬롯2~5만 토글 가능
│
├─ unitVolumeMatrix[7][5]      : 요일(월~일) × 슬롯 = 35칸 정수
│
└─ versions[] (변경 이력)
   ├─ versionNo                : v1, v2 …
   ├─ createdAt / createdBy
   ├─ status                   : 현재 적용 | 이전 버전
   ├─ effectiveFrom            : 적용 시작일 (예약 저장 시 미래 지정)
   └─ memo                     : 변경 메모
```
