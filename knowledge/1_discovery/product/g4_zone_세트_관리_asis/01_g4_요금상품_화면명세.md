## 공통 UI 규격

### 레이아웃

```
┌──────────┬────────────────────────────────────────────────┐
│          │ [breadcrumb: G4 요금 상품 관리 > {메뉴} > {화면}]│
│  좌측    │ H1 화면 제목            [우상단: ● 필수 입력 사항]│
│  메뉴    ├────────────────────────────────────────────────┤
│  (접기   │                                                │
│   가능)  │           본문 (섹션별 가로 구분선으로 분리)     │
│          │                                                │
│          ├────────────────────────────────────────────────┤
│          │ 하단 고정 바   [삭제(좌)]        [버튼들(우)]   │
└──────────┴────────────────────────────────────────────────┘
```

- 다크 테마. 섹션 제목(h3)은 파란색, 필수 표시는 주황 점(`●`)
- 본문은 내부 스크롤 컨테이너를 가짐 (하단 버튼 바 고정)
- 목록 화면 우상단은 `초기화` 버튼 (분홍/빨강 계열)
- 상세·생성 화면 우상단은 `● 필수 입력 사항` 안내

| 순서 | 섹션 | 판가 | 원가 | 할증 | 프로모션 |

| 1 | 기본 정보 | ○ | ○ | ○ | ○ |
| 2 | 요금/금액 정보 | ○ | ○ | ○ (금액 정보) | ○ (요금 정보, 3번째) |
| 3 | 할증 설정 | - | - | ○ | - |

> 섹션 제목이 `이력 정보`(판가·프로모션)와 `이력정보`(원가·할증)로 갈립니다.

### 공통 컴포넌트

| 컴포넌트 | 규격 |
|----------|------|
| VAT 배지 | 금액 입력창 오른쪽에 초록 테두리 pill, 내용 `VAT포함 N원`. 입력값 × 1.1 즉시 반영 |
| 이력 정보 | `textarea` (disabled·readonly). 한 줄 형식: `[YYYY-MM-DD HH:mm:ss] {액션} (변경유저:{이름}  {팀})` — 이름과 팀 사이 공백 2칸 |

## 화면 2. ZONE 판가 요금제 조회 / 추가

- **조회 URL:** `/zone/sales-pricings/{id}` (예: 동대문1zone = 3)
- **추가 URL:** `/zone/sales-pricings/new`
- **breadcrumb:** … > ZONE 판가 요금제 조회 (**추가 화면도 동일하게 "조회"**)
- **H1:** `ZONE 판가 요금제 조회 - {요금제명}` / 추가 시 `ZONE 판가 요금제 조회 -` (뒤에 대시만 남음)
- **스크린샷:** `09_판가_조회.png`, `12_판가_추가.png`

### 섹션 1. 기본 정보

| 필드 | 필수 | 타입 | 규격 | 조회값 (동대문1zone) | 추가 기본값 |
|------|:----:|------|------|---------------------|------------|
| 요금제명 | ● | text | - | 동대문1zone | 빈값 |
| 요금제 설명 | | textarea | placeholder `100자 이내`, maxlength 100 | 동대문 존 적용을 위한 판가 요금제 | 빈값 |

**검증 문구:** 정상 시 `올바른 요금제명입니다.` / 빈값 시 `요금제명은 필수 입력값입니다.`

### 섹션 2. 요금 정보

| 필드 | 필수 | 타입 | 규격 | 조회값 | 추가 기본값 |
|------|:----:|------|------|--------|------------|
| 기본 판가 (VAT 미포함) | ● | text (숫자, 천단위 콤마) | 우측 VAT 배지 | 4,300 | 0 |

**검증 문구:** 정상 `올바른 기본 판가 (VAT 미포함)입니다.` / 범위 초과 `금액은 1원이상 10만원 이하로 입력해주세요.`

#### 하위 블록: 거리별 요금 (h4)

행 반복 구조. 추가 화면에서는 행이 0개이고 `추가` 버튼만 노출됩니다.

한 행의 구성 (좌 → 우):

```
[구간 시작(㎞)] 이상 → [구간 끝(㎞)] 미만 → [요금제 ▾] [단위거리] [요금(원) (VAT 미포함)]  [−] [+]
```

| 필드 | 필수 | 타입 | 규격 | 비고 |
|------|:----:|------|------|------|
| 구간 시작(㎞) | ● | text | **disabled** | 첫 행은 0, 이후 행은 직전 행의 `구간 끝` 값이 자동 승계 |
| 구간 끝(㎞) | ● | text | maxlength 6, placeholder `구간 시작 초과` | 편집 가능 |
| 요금제 | ● | 커스텀 드롭다운 | 옵션 `정액제` / `거리별` | - |
| 단위거리 | ● | text | maxlength 6 | **요금제 = 정액제면 disabled(0)**, 거리별이면 편집 가능 |
| 요금(원) (VAT 미포함) | ● | text | - | - |
| `−` 버튼 | | 빨간 원형 아이콘 | 행 삭제 | 모든 행에 존재 |
| `+` 버튼 | | 빨간 원형 아이콘 | 행 추가 | **마지막 행에만** 존재 |

**고정 텍스트:** `이상`(구간 시작 뒤), `미만`(구간 끝 뒤), `→`(화살표)

#### 하위 블록: 요금 정보 요약 (회색 박스)

3개 텍스트로 구성됩니다.

| 위치 | 내용 (동대문1zone) |
|------|-------------------|
| 좌측 제목 | `요금 정보 요약` |
| 좌측 설명 (작은 글씨) | `거리별 요금 존재 시 기본판가 + 거리별 요금 최고가의 합산 VAT 포함 금액` |
| 우측 상단 (작은 글씨) | `기본판가 4,300원 + 거리별 최고가(거리별) 9,000원` |
| 우측 하단 (강조) | `VAT 포함 최대 14,630원` |

> 계산 검증: 거리별 최고가 = (10 − 1) ÷ 0.1 × 100 = 9,000원. (4,300 + 9,000) × 1.1 = 14,630원 ✓

### 섹션 3. 적용 ZONE 선택

- **안내문구:** `» ZONE별로 1개의 판가 요금제만 적용 가능합니다. 요금제는 복수의 ZONE에 적용할 수 있습니다.`
- **테이블 헤더:** `#` / `ZONE명` / (삭제 컬럼)
- **좌하단:** `+ ZONE 추가` → ZONE 검색 모달
- **우측:** `총 N개`

> 조회 화면에서 **행 0개**로 표시됩니다. 이력에 "판가 정책 Zone 추가"가 남아 있고
> ZONE 필터 검색으로는 매핑이 확인되므로, 이 테이블 자체의 조회 결함으로 보입니다.

### 섹션 4. 이력 정보

`textarea` (disabled). 동대문1zone 실제 내용:

```
[2026-05-26 10:32:08] 판가 정책 Zone 추가 (변경유저:정희연  PO팀)
[2026-05-26 10:32:08] 판가 구간 수정 (변경유저:정희연  PO팀)
[2026-05-26 10:30:09] 판가 구간 생성 (변경유저:정희연  PO팀)
[2026-05-26 10:30:09] 판가 정책 생성 (변경유저:정희연  PO팀)
```

기록되는 액션: `판가 정책 생성` / `판가 정책 수정` / `판가 구간 생성` / `판가 구간 수정` / `판가 정책 Zone 추가`

> **추가 화면에도 이 섹션이 빈 상태로 존재합니다.** (아직 이력이 있을 수 없음)

### 하단 버튼

`목록으로` `저장` (우측 정렬) — 조회·추가 동일. 삭제 버튼 없음.

#### 3-B. 요일 및 시간대 할증

섹션 제목 옆에 검증 배지가 붙습니다 (오류 시 빨간 pill):
`요일 및 시간대 설정에 올바르지 않은 범위가 포함돼있습니다.`

월~일 7행. 각 행의 구성:

```
{요일}
[HH]:[MM] ~ [HH]:[MM]   [HH]:[MM] ~ [HH]:[MM]   [일괄적용]   ├─── 타임라인 바 ───┤
  ← 시간대 1 →            ← 시간대 2 →                        06:00 12:00 18:00 24:00
{행별 검증 문구}                                                            최대 29:59
```

| 요소 | 규격 |
|------|------|
| 시간 입력 | 요일당 **2개 시간대**, 각 시간대는 시작 `HH`/`MM` + 종료 `HH`/`MM` = 입력창 4개 |
| 값 입력 시 | 입력창 옆에 `✕` 버튼이 생겨 해당 시간대를 비울 수 있음 |
| `일괄적용` | 회색 pill 버튼. 해당 요일 설정을 다른 요일에 복사하는 기능으로 추정 |
| 타임라인 | 우측 시각화 바. 눈금 `06:00` `12:00` `18:00` `24:00`, 우측 끝 라벨 `29:59` |
| 설정 구간 | 파란 선으로 표시 + 종료시각 텍스트 (예: `23:59`) |

**타임라인이 29:59까지 있는 이유:** 심야 구간을 익일 시각으로 표현합니다.
자정을 넘기는 할증은 `24:00`~`29:59`(= 익일 05:59)로 입력해야 합니다.

**행별 검증 문구 (실제로 확인된 3가지):**

| 문구 | 의미 |
|------|------|
| `○ 올바른 시간대 설정입니다` | 정상 (초록) |
| `✗ 첫 번째 종료 시간이 잘못됐습니다` | 시간대 1의 종료가 시작보다 이르거나 규칙 위반 (빨강) |
| `✗ 두 시간대가 겹칩니다` | 시간대 1과 2가 중복 (빨강) |

**동대문 1_주말전체 실데이터 (운영 중, 검증 오류 상태):**

| 요일 | 시간대 1 | 시간대 2 | 검증 결과 |
|------|---------|---------|----------|
| 월 | 00:00 ~ 03:00 | - | ✗ 첫 번째 종료 시간이 잘못됐습니다 |
| 화~금 | - | - | ○ 올바른 시간대 설정입니다 |
| 토 | 06:00 ~ 23:59 | - | ○ 올바른 시간대 설정입니다 |
| 일 | 06:00 ~ 23:59 | 00:00 ~ 03:00 | ✗ 두 시간대가 겹칩니다 |

> **운영 중인 데이터가 현재 검증 규칙을 통과하지 못합니다.**
> 의도는 "주말(토·일) 06:00~익일 03:00"이었을 텐데, `24:00~27:00`이 아니라 `00:00~03:00`으로 입력돼
