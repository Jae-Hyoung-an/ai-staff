# 파트 1. ZONE 관리 (영업 관리)

지점을 ZONE으로 승격시키고, 그 ZONE이 담당하는 지리적 권역(픽업지·배송지)을 확인하는 화면입니다.
G4 요금 상품과 세트 관리가 참조하는 **ZONE 마스터의 원천**입니다.

## 화면 1-1. ZONE 관리 (목록)

- **URL:** `/sales/zones`
- **breadcrumb:** 영업 관리 > ZONE 관리
- **H1:** ZONE 관리
- **우상단:** `초기화`
- **스크린샷:** `01_zone관리_목록.png`

### 검색 조건

| 필드 | 타입 | 규격 | 기본값 |
|------|------|------|--------|
| ZONE 이름 | text | placeholder `Zone명으로 검색` | 빈값 |
| (검색) | 아이콘 버튼 | 파란 pill, 우측 끝 | - |

> 라벨은 `ZONE 이름`(대문자 ZONE)인데 placeholder는 `Zone명`(파스칼)입니다. 표기가 섞여 있습니다.

#### 하위 블록: 지도 + 권역 목록 (2열 레이아웃)

**좌측: NAVER 지도**

| 요소 | 내용 |
|------|------|
| 범례 (좌상단 박스) | `■ 세일즈 권역` (파랑) / `■ 픽업지` (노랑) / `■ 배송지` (보라) |
| 컨트롤 | 우측 `+` / `−` 줌 슬라이더 |
| 표시 | 권역 경계를 폴리곤으로 오버레이 |

**우측: 픽업지 블록 → 배송지 블록 (수직 배치)**

각 블록의 구성:

```
총 N개
┌──────────────────────────┐
│ 픽업지명                  │   ← 폴리곤 그룹 목록 (스크롤)
│ 성북 1 zone              │
│ YOGIYO_OD                │
│ YOGIYO_DIRECT            │
└──────────────────────────┘
( ) 행정동   (●) 법정동        ← 라디오 (기본: 법정동)
┌──────────────────────────┐
│ 지역종류 │ 픽업지명        │   ← 지역 목록 (스크롤, 최대 높이 고정)
│ 법정동   │ 길음동          │
│ 법정동   │ 돈암동          │
│ …                        │
└──────────────────────────┘
```

**성북 1 실데이터:**

| 블록 | 폴리곤 그룹 (총 3개) | 지역 건수 |
|------|---------------------|----------|
| 픽업지 | 성북 1 zone / YOGIYO_OD / YOGIYO_DIRECT | 36건 (법정동) |
| 배송지 | 성북 1 zone / YOGIYO_OD / YOGIYO_DIRECT | **246건** (법정동) |

> **배송지가 픽업지의 약 7배**입니다. 성북에서 픽업해 서울 전역으로 배송하는 구조가 확인됩니다.
> (배송지 목록에 가회동·견지동·경운동 등 종로·중구 지역이 포함)

**테이블 헤더 오류:** 두 번째 테이블의 헤더가 `지역종류` / `픽업지명`인데
실제 셀에는 **동 이름**이 들어갑니다. `지역명`이 맞습니다. (배송지 블록도 동일 — `배송지명`) → 03번 문서 B-6

**레이아웃 문제:** 지도는 상단에만 있고, 배송지 블록 옆(좌측)은 **빈 공간**입니다.
지도가 sticky하지 않아 배송지 목록을 보는 동안 지도가 화면에서 사라집니다. → 03번 문서 I-6
