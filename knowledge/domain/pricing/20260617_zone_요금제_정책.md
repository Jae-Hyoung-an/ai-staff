# ZONE 요금제 (G4 요금제) 정책 정리

> ZONE(배송 권역) 기준으로 G4(직영센터) 상점의 판가·원가·할증·프로모션을 차등 적용하는 가격 정책.
> 출처: 노션 `ZONE 요금제 정책서(Policy)_v2.0` (2026-06-17) + `Zone 요금제(G4요금제)` QA 위키 (2026-06-23)
> 작성일: 2026-06-17 / 용도: 정책 이해를 위한 KB (개선 항목 작성 시 참조)

---

## 0. 한 줄 정의

ZONE 요금제는 **직영센터(G4) 상점이 속한 배송 권역(ZONE)**을 기준으로 판가·원가·할증·프로모션을 차등 적용하는 가격 정책이다. 상점은 ZONE만 선택하면 해당 ZONE에 사전 매핑된 요금제 세트가 자동 연결되며, 모든 요금 항목은 ZONE별 **영업기준표 가이드라인 범위 내에서만** 등록·수정이 가능하다.

---

## 1. 핵심 구조 — 통합 요금제

- **통합 요금제** = 원가/판가/할증/프로모션을 묶어 ZONE에 매핑하는 **최소 단위**
- 구성: `원가 1(필수) + 판가 1(필수) + 할증 N(선택) + 프로모션 N(선택)`
- **ZONE : 통합 요금제 = N : 1**
  - 하나의 통합 요금제는 여러 ZONE에 적용 가능
  - 하나의 ZONE은 단일 통합 요금제와만 매핑
- 요금제(원가/판가)는 ZONE에 **직접 매핑되지 않고**, 통합 요금제의 연결 요금제로 등록되어 통합 요금제를 통해 ZONE에 적용된다.

> **구조 진화 이력**: v1.x 초기엔 요금제↔ZONE 1:1 직접 매핑 → 중기 `요금제 SET` 개념 → v1.7~v2.0 `통합 요금제(N:1)` 구조로 전환.

### 1.1 적용 흐름 (상점은 ZONE만 선택)

```
1. UI에서 사용자가 zone_uuid(ZONE) 선택
2. 시스템이 요금제 서비스에 zone_uuid 질의 → 매핑된 Pricing Policy UUID 조회
3. 조회된 Pricing Policy UUID를 상점 레코드에 저장
```

- 상점에 요금제를 **직접 매핑하는 흐름은 없다.** 항상 ZONE을 매개로 연결.
- 적용 대상: 영업구분이 `직영센터`(=G4)인 상점만. 그 외 영업구분 상점에는 ZONE 요금제 항목 자체가 미노출.
- 상점 주소 기준 ZONE 자동 적용, **동일 ZONE 내 상점별 요금제 선택은 불가.**
- ZONE-통합요금제 매핑은 실시간 적용. 변경 시점 이후 신규 오더부터 적용되며, **진행 중인 오더 요금은 변경되지 않는다.**

### 1.2 Pricing Policy UUID

판가/원가/할증/상점 프로모션을 하나의 세트로 묶는 키. 시스템 내부 매핑 흐름은 `zone_uuid → Pricing Policy UUID → 상점 레코드`. ZONE을 쓰지 않는 요금제(G1 이관 등)는 요금제명을 직접 검색해 UUID를 직접 연결.

## 2. 요금제 구조 (판가 / 원가)

- (공통) 모든 금액은 **VAT 미포함, 반올림** 처리.

### 2.1 판가 요금제 (상점 청구 = 매출)

| 구성 항목 | 금액(기준) | 참고 |
|-----------|-----------|------|
| 배송판가 | 4,100원 / 건 | 기본단가 별도, 거리별 요금제 |

### 2.2 원가 요금제 (라이더 지급 = 비용)

| 구성 항목 | 금액(기준) | 참고 |
|-----------|-----------|------|
| 라이더비 | 3,600원 / 건 | 라이더비 별도, 거리별 요금 |
| 관제비 | 0원 / 건 | |
| 관리비 | 150원 / 건 | 직영센터: 적립 후 본사 회수 / 위탁지점: 공유콜 수행 지점 적립 |
| 픽업비 | 0원 / 건 | 배송 완료 후 지급 (분배 형태 비노출) |
| 완료비 | 0원 / 건 | 배송 완료 후 지급 (분배 형태 비노출) |

- 가이드라인 검증 기준 = `픽업비 + 완료비 + 라이더비(기본원가 + 거리별 요금)` 합산.

### 2.3 요금 책정 방식

```
최종 요금 = 기본 판가 + 거리별 요금
```

- 거리 구간 타입
  - **정액제 구간**: 구간 내 어느 거리든 동일 단일 금액 (누적되지 않음)
  - **거리별 구간**: 단위 거리당 단가 × 거리 (통과 거리에 비례 누적)
- 거리별 요금 책정: **주문 거리가 도달한 가장 먼 구간의 타입에 따라 결정**
  - 가장 먼 구간이 정액 → 해당 정액 금액으로 확정 (이전 구간 무시)
  - 가장 먼 구간이 거리별 → 직전 정액 구간 금액(없으면 0) + 통과한 거리별 구간 누적 합산
- **설정되지 않은 거리 구간의 오더는 마지막 구간 기준으로 계산 가능한 최대 금액을 적용.**

| 거리 구간 구성 | 주문 거리 | 거리별 요금 |
|----------------|-----------|-------------|
| 0~3km 거리별(100원/0.1km) → 3~10km 정액(10,000원) | 5km | 10,000원 |
| 0~3km 정액(4,000원) → 3~10km 거리별(100원/0.1km) | 2km | 4,000원 |
| 0~3km 정액(4,000원) → 3~10km 거리별(100원/0.1km) | 5km | 6,000원 |
| 0~2km 정액(4,000원) → 2~3km 정액(6,000원) | 2.5km | 6,000원 |

### 2.4 수행 거리 소수점 처리

- 단위 거리 = 거리별 요금 단가 적용 단위 (예: 0.1km)
- **원가 요금제: 단위 거리 소수점 미만 버림**
- **판가 요금제: 단위 거리 소수점 미만 반올림**
- 예: 단위 0.1km, 수행 1.567km → 원가 1.5km / 판가 1.6km

### 2.5 과적 처리

- 과적 = 한 라이더가 한 건의 오더를 한 번에 수행 못 할 때 추가로 붙는 오더.
- 과적 오더 요금 = 원오더와 동일(기본단가·거리별·할증·프로모션 모두). 단, **재배송은 제외**(프로모션 적용 X).

### 2.6 취소 및 환급 (참고 — 연관 정책)

- 부릉 인트라 취소: 배송비 환급 안 됨, VCC 예치금 조정으로 수기 환급 (`배송 > 취소환급 조정`)
- 부릉 POS 취소(상점 취소): 취소수수료 차감 후 배송비 환급 (`배송 > 취소`)

## 3. 프로모션

> 마케팅 목적으로 기본 요금에 추가 적용되는 전략적 비용. (공통) VAT 미포함, 반올림.

- 대분류: 상점 프로모션 / 라이더 프로모션. 상점 프로모션 소분류로 일반 / **제로패스(P1)**.
- G4 상점에 한해 설정 가능. 원·판가 금액 **마이너스 입력 허용**(상점 할인, 라이더 차감).
- 검증: **1차** 프로모션 생성 시 영업기준표 범위 / **2차** 상점 매핑 시 `기설정 프로모션 + 신규 프로모션` 합산.
- 상점별 자동 상태 판정: `적용완료`(합산 범위 내, 즉시 적용) / `적용불가`(범위 밖, 차단).
- 수정·삭제: 배송 이력 있으면 단가 수정 금지, 1개 상점이라도 매핑 시 삭제 불가(폐점 제외). 삭제 이력도 로그 보존.
- 권한: 별도 권한 없이 등록/수정/조회 허용.

### 3.1 제로패스 프로모션 (P1)

- 기본 판가만 무료(0원) 처리하는 특수 프로모션 (거리별 요금 제외, 기본 판가만 대상)
- 상점당 누적 횟수 **5회 제한**, 동일 기간 내 상점당 **1개**만 설정
- 배송완료 후 취소된 오더에 한해 적용 횟수 원복, 취소 수수료 차감에서 제외

## 4. 할증

> 실시간 배달 환경 변화(기상·수요·지역)에 대응해 기본 요금 위에 가산되는 가변 비용. (공통) VAT 미포함, 반올림.

| 유형 | 정의 | 참고 |
|------|------|------|
| 기상 할증 | 기상 악화(눈·비·태풍)로 배달 난이도 급상승 시 | **ZONE당 1개만** 매핑 |
| 시간대 할증 | 피크타임·특정 요일 수급 불균형 해소 | 요일별 최대 2구간 |
| 폴리곤 할증 | 지형 특성·상습 정체 구역 출입 시 | 픽업지/도착지/통합 구분, 픽업·배송지 각 5개 |
| 특수 할증 | 위 3종 외 일시·예외 상황 | 명절·축제·국가 행사 등 |

- 원·판가 할증을 나누지 않고 자유 입력, 하나의 항목으로 관리(둘 중 하나만 입력해도 저장 가능).
- 통합 요금제에 등록 → ZONE 내 모든 상점에 **일괄 적용**(상점별 개별 매핑 없음).
- 검증: 통합 요금제 저장 시 `기설정 할증 + 신규 할증` 합산이 영업기준표 범위 내인지 2차 검증, 이탈 시 저장 차단.

## 5. 통제·관리 정책 (무결성·보안)

### 5.1 영업기준표 가이드라인 검증 (핵심 통제)

- 저장 시 매핑된 **모든 ZONE 각각**에 대해 가이드라인 범위 검증.
- **1원이라도 이탈 시 저장 원천 차단, 예외 승인 없음.**
- 할증·프로모션은 기존 적용 금액과 **합산** 기준 검증.
- 이탈 시 어떤 ZONE이 어떤 사유로 벗어났는지 팝업 안내.

### 5.2 판가-원가 거리 구간 정합성 검증

- 판가 요금제 ZONE 매핑 시점에 해당 ZONE 원가 요금제와 **거리별 요금 구간 동일 여부** 검증. 다르면 적용 차단 (동일 거리 정산 오류 방지).

### 5.3 수정·삭제 제약

- 배송 수행 이력 있는 원가/판가 요금제: **단가 수정 금지**. 단, ZONE 매핑 변경·할증/프로모션 추가는 허용.
- 단가 변경 필요 시: 신규 통합 요금제 생성 후 ZONE 매핑 교체만 허용.
- 1건이라도 배송 이력 있는 요금제 **삭제 불가**.
- 통합 요금제에 연결된 상태에서는 수정 불가 → 연결 해제 후 수정.
- 할증·프로모션은 ZONE이 1개라도 매핑되면 **핵심 정보 수정 차단**(금액·종류·기간). 단 ZONE 추가는 허용. (2026-03-16 정책)

### 5.4 활성화 상태

- `활성화`: ZONE 1개 이상 연결 / `비활성화`: 연결 ZONE 0개. 사용자가 직접 변경 불가, 매핑 추가/해제 시 시스템 자동 갱신.

### 5.5 이력 관리

- 생성·수정·매핑 변경 시점과 작업자 로그 기록.
- 매핑 교체 시 과거 매핑 이력 타임라인 관리.
- 매핑 변경돼도 **완료된 과거 배달 건의 정산 스냅샷은 불변.**

### 5.6 권한

- 통합 요금제/요금제/할증 생성·수정: **BTF, 사업기획팀**만. 조회는 인트라 전체 허용.
- 프로모션: 별도 권한 없이 등록/수정/조회 허용.

## 6. 시스템 장애 대응

### 6.1 우선순위

1순위 **주문 연속성**(가용 fallback 총동원해 정상 생성) → 2순위 **주문 차단**(모든 fallback 불가 시에만). 요금 오차는 사후 보정, 상점·라이더 불이익 없도록.

| 장애 상황 | 대응 |
|-----------|------|
| 요금제 관리/계산 서버 장애 | Fallback 단가표(직선거리) 적용 + 정상 생성 + `장애` 태그 |
| 두 서버 모두 장애 | G4 주문 접수 일시 차단 (1급 장애) |

> 장애 감지 조건·복구 기준은 **개발팀과 별도 정의** (정책서 상 미확정).

### 6.2 Fallback 단가 (VAT 미포함, 1.5km 기본거리 포함, 초과분 직선거리)

| 구분 | 금액 |
|------|------|
| 기본 판가 | 4,000원/건 |
| 기본 라이더비 | 3,500원/건 |
| 관제·관리비 | 150원/건 |
| 거리할증 | 100원/100m (1.5km 초과분) |

### 6.3 사후 보정

- 장애~복구 구간 오더에 `장애` 태그 자동 부여, fallback 요금 정산 스냅샷에 기록(수정·삭제 불가).
- 복구 후 개발팀이 배치로 정상 요금 재계산 → 보정 리스트(오더 ID·상점/라이더·fallback/정상/차액) 추출 → **운영에서 수기 정산.**

## 7. 사용자별 화면 (요약)

| 사용자 | 화면 | 핵심 |
|--------|------|------|
| 운영자(BTF/사업기획) | Vroong Intra `[ZONE 요금 상품 관리]` | 원가/판가/할증/폴리곤편집기/G4프로모션 5개 하위 메뉴, 등록 후 ZONE 매핑 |
| 운영자(BTF) | 상점관리 | `기본정보>운영정보`에 ZONE 드롭다운(필수, 권한자만) / `요금정보>배송비정보`에 적용 요금제 읽기전용(판가 기준) |
| 운영자 | 기사·지점관리 | ZONE 읽기전용 노출 |
| G4 상점주(P1) | 상점POS | 제로패스 횟수/소진, `제로패스` 태그, "기본요금만 무료" 안내 |
| G4 라이더 | 부릉플러스 앱 | 화면별 데이터 구조 상이 (아래 §7.1) |

### 7.1 부릉플러스 앱 화면별 배송료 데이터 구조

| 화면 | 엔드포인트 | 합산 주체 | 내역 분리 | 신규 요금 추가 시 영향 |
|------|-----------|-----------|-----------|------------------------|
| 오더 추천 수락 | NATS/FCM `dispatch.offer.created` | 클라이언트(`agentFee+extraChargeFee`) | 없음 | **클라이언트 수정 필요** |
| 진행 중 배달 | `GET /aggregate/api/plus-app/v1/tasks/current` | - | 미표시 | 영향 없음 |
| 배달 내역 상세 | `GET /aggregate/api/plus-app/v1/order-completions/list` | 서버(`totalFee`) | 항목별 표시 | 서버 `extraCharges` 추가만 |

> 배송 내역 화면에서는 기상 할증만 별도 `기상 할증` 항목으로 노출, 그 외 할증은 배송료에 합산.

---

## 8. ZONE 매핑 규칙 요약

- **판가**: 1개 요금제 → 다수 ZONE 가능, 단 ZONE당 1개
- **원가**: 1개 요금제 → 다수 ZONE 가능, 단 ZONE당 1개
- **할증**: 1개 → 다수 ZONE 가능, 단 기상 할증은 ZONE당 1개
- **프로모션**: 상점/라이더 분리, 제로패스는 동일 기간 상점당 1개
