## 1. 영업존 · 판가

| # | 시나리오 |
|---|---------|
| 1-1 | 담당자는 영업존을 생성하고 지점과 픽업지 권역 1개를 연결할 수 있다 |
| 1-2 | 담당자는 판가 요금제에서 적용 영업존·거리별 판가·적용 판가 할증을 설정할 수 있다 |
| 1-3 | 담당자는 판가 할증을 생성·관리할 수 있다 |
| 1-4 | 시스템은 이미 다른 영업존에 연결된 픽업지 권역의 선택을 차단한다 |
| 1-5 | G4 상점은 오더 접수 시 소속 영업존의 판가·할증·프로모션을 자동 적용받는다 |
| 1-6 | 시스템은 다른 지점의 픽업지 권역과 지리적으로 겹치면 경고를 표시한다 |
| 1-7 | 담당자는 영업존에 배송 반경을 설정하여 상점 판매권역을 결정할 수 있다 |

### 1-1 영업존 생성

영업존은 **지점 1개 + 픽업지 권역 1개**로 구성한다. 지점이 픽업지 권역을 여러 개 보유하면 각각을 별도 영업존으로 만들 수 있다(지점 : 영업존 = 1:N).

| 동작 | 내용 |
|------|------|
| 지점 선택 | 벤더존 운영방식 지점만. 선택 가능한 픽업지 권역이 남아 있지 않은 지점은 비활성 + 이유 표시. 매핑 후 교체 불가 |
| 픽업지 권역 선택 | 지점 보유 픽업지 권역 목록에서 **라디오 단일 선택**. 이미 다른 영업존에 연결된 권역은 비활성 |
| 지도 표시 | 선택한 픽업지 권역 폴리곤 1개만 표시. 미선택 시 플레이스홀더 |
| 지역 목록 | 선택한 권역에 포함된 지역만 (행정동/법정동 전환) |

**채널별 판가 확장**: 성북 지점의 `성북 1 zone` / `YOGIYO_OD` / `YOGIYO_DIRECT`를 각각 별도 영업존으로 만들면 채널별로 다른 판가를 적용할 수 있다. 7/14 회의의 "멀티 채널 판가 확장 가능성"에 대응한다.

### 1-2 판가 요금제 설정

| 섹션 | 내용 |
|------|------|
| 기본 정보 | 요금제명 / 요금제 설명 |
| 요금 정보 | 기본 판가 + 거리별 요금(구간 반복) + 요약 |
| 적용 영업존 선택 | 검색 모달로 추가. 영업존당 요금제 1개, 요금제는 복수 영업존 가능 |
| 적용 판가 할증 선택 | 1-3에서 만든 판가 할증 중 복수 선택. 적용 해제 가능 |
| 이력 정보 | 변경 이력 |

- 통합 요금제를 경유하지 않고 판가 요금제가 영업존을 직접 보유한다.
- 화면은 탭으로 나누지 않고 단일 페이지 섹션 구조를 유지한다.

### 1-3 판가 할증

| 동작 | 내용 |
|------|------|
| 금액 정보 | `판가 할증 금액`만 입력(필수). 원가 금액 필드는 없다 |
| 할증 종류 | 기상 / 요일 및 시간대 / 지역 폴리곤 / 특수 |
| 적용 대상 | 영업존 (복수 선택 가능) |
| 양방향 반영 | 판가 요금제에서 할증을 선택하면 할증 화면의 적용 영업존에도 반영되고, 그 역도 성립 |

### 1-4 픽업지 권역 중복 연결 차단

- 하나의 픽업지 권역은 **하나의 영업존에만** 연결된다. 이미 연결된 권역은 선택 목록에서 비활성 처리되고, 연결된 영업존명을 함께 보여준다.
- 하나의 상점(픽업지)이 두 개의 판가를 갖는 상황을 원천 차단하는 장치다.

### 1-5 G4 자동 적용

| 항목 | 내용 |
|------|------|
| 판정 기준 | **관제지점 소속 + 영업구분 직영센터** |
| 적용 대상 | 판가 요금제 + 판가 할증 + G4 프로모션 |
| 예외 | 상점 상세에서 수동 오버라이드 가능. 화면에 판정 근거를 함께 표시 |

> 상점 주소 기준을 쓰지 않는 이유: 지점 관할 밖에 있으나 해당 지점이 관제하는 상점에서 판가와 정산 주체가 어긋난다.

### 1-6 지리 중첩 경고

같은 지점의 채널별 픽업지 권역은 지리적으로 동일 지역을 덮는 경우가 많다. 따라서 지리적 중첩은 저장을 막지 않고 경고만 표시한다.

| 동작 | 내용 |
|------|------|
| 감지 대상 | **다른 지점**의 픽업지 권역과의 지리적 중첩 |
| 표시 | 영업존 상세에 경고 배너, 목록에 `⚠ 중첩` 배지 + 상대 권역명 |
| 저장 | **허용**. 지점 관할 중복 문제이므로 지점 쪽에서 정리한다 |
| 사후 감지 | 지점이 픽업지 권역을 확장해 사후 중첩이 생기면 재검증 후 배지 갱신 + 담당자 알림 |

### 1-7 배송 반경 · 상점 판매권역

| 항목 | 내용 |
|------|------|
| 입력 | 영업존 상세에서 **배송 반경(km) 단일값** |
| 생성 규칙 | 영업존의 픽업지 권역 + 배송 반경 = 상점 판매권역(`STORE_SALES_REGION`) |
| 적용 대상 | **G4(직영센터) 상점 한정** |
| 상점별 개별 설정 | 제공하지 않는다 (Out-of-Scope) |

> 소스를 관제지점 공급권역에서 영업존 픽업지 권역으로 옮기는 이유: 공급권역이 벤더 배송권역 소스로 전용되고 중첩이 허용되면 상점의 주문 가능 범위가 벤더 권역 변경에 흔들린다. 영업(존) 쪽에 귀속시켜 격리한다.

## 2. 벤더 배송권역 · 원가

| # | 시나리오 |
|---|---------|
| 2-1 | 담당자는 지점 공급권역을 불러와 벤더 배송권역을 생성할 수 있다 |
| 2-2 | 담당자는 배송권역 정책에 배송권역을 연결할 수 있다 |
| 2-3 | 담당자는 원가 요금제 탭에서 기본 거리와 고정비 4항목을 입력할 수 있다 |
| 2-4 | 담당자는 요일 × 슬롯 라이더비 표를 입력할 수 있다 |
| 2-5 | 담당자는 거리 할증을 구간(시작~끝)별로 추가해 설정할 수 있다 |
| 2-6 | 담당자는 원가 할증 메뉴에서 할증을 만들고, 배송권역 정책에 선택해 적용할 수 있다 |
| 2-7 | 담당자는 권역 외 할증을 등록하고 금액을 설정할 수 있다 |
| 2-8 | 담당자는 세트분배 관리에서 벤더와 발주 세트 수를 선택할 수 있다 |
| 2-9 | 시스템은 슬롯 변경 시 변경된 슬롯의 원가만 재입력을 요구한다 |
| 2-10 | 담당자는 권역·원가 설정의 변경 이력(버전)을 조회·비교할 수 있다 |

### 2-1 벤더 배송권역 생성

생성 경로는 **지점 공급권역 불러오기 하나뿐**이다. 폴리곤을 직접 그리거나 편집하는 기능은 제공하지 않는다.

| 항목 | 내용 |
|------|------|
| 생성 방식 | `+ 지점 공급권역 불러오기` 모달에서 지점·공급권역 선택 |
| 폴리곤 관계 | 참조한 공급권역과 **항상 동일**하게 유지된다. 공급권역이 변경되면 배송권역도 함께 변경된다 |
| 폴리곤 수정 | 배송권역 화면에서는 불가. `권역 관리`에서 원본 공급권역을 수정한다 |
| 중복 참조 | 같은 정책 안에서 동일 공급권역을 두 번 참조할 수 없다 |
| 타 정책과 중첩 | 허용. 다른 정책이 쓰는 공급권역도 선택할 수 있다 |

- 지점 공급권역은 **지오메트리 소스로만 재활용**하며, 영업기준(도착권역) 역할은 폐기한다.
- 중첩은 ① 한 정책이 여러 지점의 공급권역을 참조 ② 서로 다른 정책이 같은 공급권역을 참조하는 두 경로로 성립한다. 임의 폴리곤 없이도 기사 공급 음영 최소화 목적을 달성한다.
- 남는 제약: 공급권역의 **일부만** 특정 벤더에게 줄 수는 없다. 필요하면 공급권역 자체를 분할한다.

### 2-2 배송권역 정책에 배송권역 연결

- `적용 ZONE 선택`을 `벤더 배송권역` 탭으로 대체한다. 정책당 1개 이상 연결한다.
- 배송권역 : 배송권역 정책 = N:1. 정책이 여러 폴리곤을 보유할 수 있다.
- 활성/비활성 판정은 **배송권역 1개 이상 + 원가 요금제 입력 완료**로 판단한다.

### 2-3 · 2-4 · 2-5 원가 요금제 입력

원가 요금제는 **배송권역 정책이 소유**한다. 배송권역은 지오메트리만 갖는다. 슬롯·벤더·세트·보상이 모두 정책 단위이므로 원가도 같은 단위여야 정산이 맞물린다.

| 구성 | 입력 단위 |
|------|----------|
| 기본 거리 | 정책 단일값 |
| **라이더비** | **요일(행) × 활성 슬롯 + 시간 외(열)** 매트릭스 |
| **거리 할증** | **다구간 구간표** (행마다 `구간 시작`~`구간 끝` + `단위 거리` + `단위당 원가`) |
| 관제비 · 관리비 · 픽업비 · 완료비 | 정책 단일값 (시간대 차등 없음) |

**고정비 4항목을 유지하는 이유**: 현행 원가 요금제는 5개 항목이고 관리비 150원은 정산에 쓰인다(직영센터는 본사 회수, 위탁지점은 적립). 라이더비만 남기면 정산이 깨진다.

**거리 할증을 다구간으로 유지하는 이유**: 별도의 `적용 상한 거리` 필드는 두지 않는다. 구간을 단계별로 추가하고 **마지막 구간의 끝을 상한으로 해석**한다. 첫 구간의 시작은 기본 거리를 자동 승계하고, 2행 이후는 직전 구간의 끝을 이어받는다.

- 현행 원가·판가가 모두 다구간이라 **구간을 그대로 이관하면 손실이 없다**. 단일 구간으로 압축하면 3구간 이상 데이터가 깨진다.
- 판가의 `거리별 요금` 테이블과 UI가 동일해져 운영자 학습 비용도 줄어든다.

### 2-6 원가 할증

| 항목 | 내용 |
|------|------|
| 생성·관리 위치 | **`G4 요금 상품 관리 > 원가 할증 관리` 메뉴** (판가 할증과 같은 층위) |
| 적용 대상 | 배송권역 정책. 할증 상세의 `적용 배송권역 정책 선택` 섹션에서 지정한다 |
| 정책 쪽 진입점 | 배송권역 정책 상세 > 원가 요금제 탭 > `적용 원가 할증 선택` 섹션 (선택·해제만) |
| 카디널리티 | 원가 할증 : 배송권역 정책 = **N:M** |
| 확정 시점 | 배차 시점. 단 **기상 할증은 완료 시점** (목록에 `확정 시점` 컬럼으로 노출) |

**별도 메뉴로 분리한 이유**: 기상 할증처럼 여러 정책에 공통 적용되는 할증을 정책 탭 안에서만 만들면 정책마다 중복 생성해야 한다. 판가 쪽 구조(판가 할증 메뉴에서 생성 → 판가 요금제에서 선택)와 대칭을 맞춘다.

### 2-7 권역 외 할증

- 정의: **출발지가 권역 내 + 도착지가 권역 외**. 회귀 오더(도착지만 권역 내)에는 적용하지 않는다.

| 산정 방식 | 입력 |
|----------|------|
| 정액 | 금액 1개 |
| 경계 초과 거리 비례 | `단위 거리(km)` + `단위당 금액` + `상한 금액` |

- UI는 양쪽을 지원하도록 설계하고, 어느 쪽을 쓸지는 **TBD-5**로 남긴다.
- 정액이면 근거리 권역 외는 과보상, 원거리는 과소보상이 된다는 점이 거리 비례 옵션을 두는 이유다.
- **미결**: 판가에도 권역 외 할증을 붙일지. 원가만 올리면 CM이 그만큼 악화된다.

### 2-8 세트분배

- 기능·화면 구조 그대로. 기준 축만 존 → 배송권역 정책으로 변경한다.
- ⚠ **확인 필요**: 벤더-존 연결을 만드는 화면 경로가 AS-IS에 없다(벤더 상세의 `소속 Zone`은 읽기 전용, 등록 화면에는 섹션 자체가 없음). 그런데 변경 이력에는 `존 연결` 기록이 남는다. 경로를 찾아야 배송권역 정책 연결로 전환할 수 있다.

### 2-9 슬롯 변경 시 원가표 동기화

| 케이스 | 동작 |
|--------|------|
| 슬롯 물량만 변경 | 원가 유지 |
| 슬롯 시간·사용 여부 변경 | **변경된 슬롯 셀만 미입력 처리**, 나머지는 유지. 미입력 셀이 있으면 저장 차단 |
| 슬롯 추가 | 신규 열이 미입력 상태로 추가 |
| 슬롯 삭제(미사용) | 해당 열 제거, 나머지 유지 |
| 반영 시점 | `예약 저장`으로 슬롯과 원가를 동일 시점에 적용 가능 |

> 슬롯 하나만 조정해도 요일 7 × 슬롯 6 = 최대 42개 셀을 전량 재입력하게 하면, 재입력 중 오류가 곧 정산 사고가 된다. 그래서 전체 초기화하지 않는다.

### 2-10 버전 관리

- AS-IS 버전 관리(저장 시 버전 적재, `예약 저장`으로 미래 시점 적용, 버전 비교 모달)를 승계한다.
- **원가 요금제·원가 할증도 버전 스냅샷에 포함**된다. 정산이 과거 시점 원가를 조회하므로 필수다.
- 비교 모달에 원가 블록(고정비 4항목 / 라이더비 매트릭스 / 거리 할증 구간표)을 추가한다.

## 3. 배차 · 원가 산정

| # | 시나리오 |
|---|---------|
| 3-1 | 시스템은 오더 생성 시 출·도착지 좌표로 후보 벤더 배송권역을 판정한다 |
| 3-2 | 시스템은 후보 벤더별로 오더를 권역 내/외/회귀로 분류한다 |
| 3-3 | 시스템은 기사 소속 벤더의 배송권역 정책 원가 + 할증으로 제안별 원가를 산정한다 |
| 3-4 | AI 배차는 분류·원가 기준으로 제안 우선순위를 정한다 |
| 3-5 | AI 배차는 기사가 권역 외에 위치할 때만 회귀 오더를 제안한다 |
| 3-6 | 기사는 제안 화면에서 산정된 배송료와 태그를 확인할 수 있다 |
| 3-7 | 시스템은 G1 벤더 오더에도 동일한 원가 판정을 적용한다 |
| 3-8 | 프렌즈 원가는 제안 가능한 가장 저렴한 벤더 원가를 기반으로 한다 |

### 3-1 권역 판정

- 출·도착지 중 하나라도 벤더 배송권역에 속하면 그 권역이 연결된 정책의 벤더 소속 기사가 제안 대상이 된다.
- 좌표 → 벤더 배송권역 판정 API가 **신설**되어야 한다 (복수 권역 반환).
- 판정 실패 시 처리는 E-8.

### 3-2 오더 3분류

| 분류 | 조건 | 제안 |
|------|------|------|
| 권역 내 | 출발지·도착지 모두 권역 안 | 일반 제안 |
| 권역 외 | 출발지만 권역 안 | 권역 외 할증 가산 |
| 회귀 | 도착지만 권역 안 | 권역 밖 기사에게 복귀 유도 |

같은 오더라도 기사 소속 벤더에 따라 분류·원가가 다르다.

### 3-3 제안별 원가

| 동작 | 내용 |
|------|------|
| 산정 기준 | 후보 기사 소속 벤더가 연결된 **배송권역 정책의 원가 요금제 + 원가 할증** |
| 권역 외 | 해당 정책에 권역 외 할증이 있으면 가산 |
| 확정 시점 | **기사 배정 시점** |
| 계산 시점 | 개발 구현 판단. 단 "대기 오더 목록에 기사별 원가 표시"를 만족해야 함 |

**리뷰에서 답할 것**

| # | 질문 |
|---|------|
| a | 원가표를 누가 만드나 — 요금제 서버 vs 라스트마일 |
| b | 후보군 조회 시점 원가와 배정 시점 원가가 다르면 어느 쪽으로 확정하나 → **E-9** |
| c | 오더 생성 후 벤더·권역이 추가되면 원가표를 갱신하나 → **E-10** |

> **참고**: AI배차 배정 요청에는 제안 금액(`agentTotalFee`)이 실려오고, 라스트마일이 기존 스냅샷과의 차액을 `AI_ADJ` 할증으로 얹는다. "기존 원가 유지 + 배정 시점 조정"이 부분 구현돼 있어 구현 출발점으로 쓸 수 있다. 단 신규 권역 원가와 이중 가산되지 않도록 해야 한다 → **E-13**.

### 3-4 AI 배차 우선순위

| 단계 | 규칙 |
|------|------|
| 1. 하드 필터 | 출·도착지 어느 쪽도 권역에 속하지 않는 후보 제외 |
| 2. 분류 정렬 | 권역 내 > 회귀 > 권역 외 |
| 3. 동순위 정렬 | 원가 낮은 순 |
| 4. 회귀 게이트 | 기사가 해당 권역 외부에 위치할 때만 회귀 오더 포함 |
| 5. 기존 우선순위와의 관계 | 삽입 위치를 배차팀과 확정 — **TBD-4** |

### 3-5 회귀 조건

- 기사가 **권역 외에 위치할 때만** 제안한다. '경계' 개념은 쓰지 않는다.
- ⚠ **확인 필요**: 기사 위치 소스. 라스트마일 후보군 조회는 기사 위치를 보지 않고, 벤더 오더 후보의 위치는 vendorset 응답에 실려온다. 이 소스를 쓸지 새로 만들지 결정이 필요하다.

### 3-6 플러스앱 표기

| 항목 | 내용 |
|------|------|
| 태그 | `회귀`(파랑) / `권역 외`(주황) |
| 금액 | 권역 외 할증 포함 금액 |
| ⚠ 제약 | 태그 노출은 **앱 수정 + 스토어 배포**가 필요하다. 서버 일정(10월 말~11월)과 함께 잡아야 한다 |
| 구버전 대응 | 태그 미노출, 금액은 정확히 표시 |

### 3-7 G1 원가 일원화

- 관제지점의 지점 타입이 벤더존인 오더는 상점 등급 무관하게 소속 벤더의 배송권역 정책 원가로 산정한다.
- 대기 오더 목록에도 **각 기사 소속 벤더 기준 원가**를 표시한다. 즉 오더 1건의 표시 금액이 보는 기사마다 다르다. 전투배차 목록은 조회 빈도가 높아 실시간 계산이 부담이므로 사전 원가표 방식이 유리하다.
- ⚠ **재무 영향**: G1은 판가 체계가 달라 CM 계산·정산 리포트에 영향이 있다. 재무 영향도 분석이 선행되어야 한다.

### 3-8 프렌즈 원가

| 항목 | 내용 |
|------|------|
| 산정 | 해당 오더의 후보 배송권역 정책들 중 **가장 낮은 원가**를 기준으로 산정 |
| 폴백 | 어떤 권역에도 속하지 않으면 폴백 원가 — **TBD-8**, E-3 |
| 일반 이륜 기사 | 동일 규칙 적용 |
| ⚠ 리스크 | 6/8 마진 분석에서 프렌즈 원가가 매출의 약 2배로 구조적 적자였다. 최저 벤더 원가 기반은 적자를 개선하지만 **프렌즈 수락률 하락** 위험이 있어 가드레일 지표로 감시한다 |

## 4. 시각화

| # | 시나리오 | 우선순위 |
|---|---------|:--------:|
| 4-1 | 담당자는 지도에서 영업존(빨강)·벤더 배송권역(파랑) 폴리곤을 한눈에 확인할 수 있다 | P0 |
| 4-2 | 담당자는 폴리곤 호버로 이름을 확인하고 클릭으로 상세에 진입할 수 있다 | P0 |

### 4-1 폴리곤 표시

| 항목 | 내용 |
|------|------|
| 표시 | 영업존 = 빨강, 벤더 배송권역 = 파랑 |

| 메뉴 위치 | **TBD-6** — AS-IS 인트라 사이드바에 `권역 관리` 그룹이 없다. 신설인지 기존 그룹 하위인지 확정 필요 |

- 중첩 구간은 **별도 강조하지 않는다.** 정확한 중첩 관계는 배송권역 정책 상세의 `중첩 정책` 컬럼에서 확인한다.

### 4-2 호버 · 클릭

| 대상 | 호버 | 클릭 |
|------|------|------|
| 영업존 | 영업존명 + 지점명 + 픽업지 권역명 | 영업존 상세로 이동 |
| 배송권역 | 정책명 + 벤더 수 + 배송권역명 | 배송권역 정책 상세로 이동 |

### 4-3 CM · CMR (P1)

| 대상 | 표시 |
|------|------|
| 영업존 | 전체 CM·CMR + 해당 지역 오더를 수행한 **배송권역 정책별 분해** |
| 배송권역 | 소속 벤더가 수행한 오더 기준 CM·CMR |
| 색상 | 그린(하한선 이상) / 옐로(경계) / 레드(미달) |

⚠ **영업기준 관리 졸업과의 관계**: 7/14의 "영업기준 관리 졸업"이 실행되면 기존 핵심 통제(영업기준표 범위 검증)가 사라진다. **졸업 시점과 CM 모니터링 가동 시점 사이의 통제 공백**을 어떻게 메울지 정해야 한다.

## 5. 엣지케이스

| # | 상황 | 왜 중요한가 | 처리 방향 |
|---|------|------------|----------|
| **E-1** | 벤더 배송권역 변경 시 진행 중 오더의 분류·원가 처리 | 정산 스냅샷 일관성 | 진행 중 오더는 **변경 전 기준으로 완료** |
| **E-2** | 한 벤더가 여러 배송권역 정책에 소속된 경우, 동일 오더의 원가 산정 기준 권역 선택 | 중첩 허용의 직접 결과 | ① 벤더:정책 카디널리티 확정(**TBD-3**) ② 복수 소속 허용 시 "가장 낮은 원가" 또는 "출발지를 포함하는 권역 우선" 등 결정 규칙 필요 |
| **E-3** | 출·도착지 모두 어떤 권역에도 속하지 않는 벤더존 오더 | 폴백 정의 필요 | 하드 필터로 벤더 기사 제안 대상에서 제외 + **폴백 원가**로 프렌즈·일반 이륜에 제안 (**TBD-8**) |
| **E-4** | 시간 외 슬롯 오더 + 슬롯 경계 시각(정각) 오더의 원가 귀속 | 경계 처리 미정의 | 경계 시각은 **다음 슬롯 시작으로 귀속**(`시작 ≤ t < 종료`). 기준 시각은 오더 생성 시각 vs 배정 시각 중 확정 필요 → E-9와 연동 |
| **E-5** | 배차 취소 → 재배차 시 원가 재산정 여부 | 배차 시점 확정 원칙의 파생 | **새 기사 기준으로 재확정**. 재확정 이력을 남긴다 |
| **E-6** | 우선배차 조건 카운트 기준 | - | **이번 스코프 제외** (우선배차 기능 자체가 Out-of-Scope) |
| **E-7** | 배송권역 정책 삭제·비활성화 시 연결 벤더·세트 발주 처리 | 라이프사이클 | 연결 벤더가 있으면 삭제 차단. 비활성화는 **세트 발주 중단 + 진행 오더는 완료까지 유지**. 활성 조건을 잃으면 자동 비활성 |
| **E-8** | 권역 판정 또는 원가 계산 실패 시 배차를 막나, 기본 원가로 진행하나 | 개발 미결 | 배차 중단은 물량 손실이 크므로 **폴백 원가로 진행 + 경보 적재** 권장 |
| **E-9** | 후보군 조회 시점과 배정 시점 사이에 슬롯이 바뀌어 원가가 달라짐 | 개발 미결 | **제안 시 보여준 금액을 보장**하고 차액은 조정금으로 처리하는 방향 권장 (`AI_ADJ` 선례) |
| **E-10** | 오더 생성 후 벤더·권역이 추가·삭제됨 (원가표 갱신 여부) | 개발 미결 | "벤더 생성 전에 만들어진 오더가 새 벤더의 후보가 되는가" → **된다**가 운영상 자연스러움 → 갱신 필요 |
| **E-11** | 벤더 배송권역 축소·삭제 시 상점 판매권역과 배송 가능 판정에 미치는 영향 | 1-7 | 영업존 귀속으로 분리했으므로 **영향 없음**이 정답. 회귀 테스트로 확인 |
| **E-12** | 지점 픽업지 권역 변경으로 다른 지점과 지리적 중첩이 **사후** 발생 | 1-6 | 차단하지 않고 감지·알림 |
| **E-13** | 기존 `AI_ADJ` 할증과 신규 권역 원가 확정의 **이중 가산** | 개발 지적 | 권역 원가 확정 후 `AI_ADJ`를 어떻게 계산할지 정의 필요 |
| **E-14** | 과적 오더의 분류·원가 | 개발 지적 | 과적 오더는 완료 시 재계산 제외 대상인데 "배정 시점 확정" 원칙과 충돌. 예외 명시 필요 |
| **E-15** | 배차포기 수수료 기준 | 개발 지적 | 포기 기사 소속 벤더의 권역 원가를 쓸지, 오더 확정 원가를 쓸지 정의 |
| **E-16** | 지점의 픽업지 권역이 삭제되어 연결된 영업존이 고아가 됨 | 1-1 (1:1 구조의 파생) | 삭제 차단 또는 영업존 자동 비활성 + 알림. 판가 공백이 생기므로 반드시 정의 필요 |
| **E-17** | 지점 담당자가 공급권역을 변경·삭제하여 벤더 배송권역이 함께 바뀜 | 2-1 (상시 연동의 파생) | 상시 연동이므로 **의도된 동작**이나 통보 없이 원가 산정 범위가 바뀐다. 참조 중인 정책·벤더에게 **변경 알림 + 이력 기록**, 삭제는 참조가 있으면 차단 |

## So What / Next Step

- 시나리오는 영업존·판가 7건, 배송권역·원가 10건, 배차·원가 8건, 시각화 3건이다. 엣지케이스는 17건이다.
- 엣지케이스 중 **E-8 ~ E-10, E-13 ~ E-15는 개발팀이 먼저 제기한 미결 항목**이므로, PRD 리뷰에서 답을 주지 않으면 개발이 진행되지 않는다.
- **E-16은 영업존 : 픽업지 권역을 1:1로 확정하면서 새로 생긴 케이스**다. 픽업지 권역이 사라지면 영업존이 판가를 잃으므로 라이프사이클 정의가 필요하다.
- **E-17은 배송권역을 지점 공급권역에 상시 연동하면서 새로 생긴 케이스**다. 지점 조직의 권역 변경이 벤더 정산에 직결되므로 알림 경로가 없으면 사고가 된다.
