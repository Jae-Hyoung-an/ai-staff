## 1. 개요

### 1.1 배경 및 문제 정의

현재 ZONE 요금제 체계는 **영업 권역(픽업)과 공급 권역(배송)이 1:1 강결합** 구조이며, 권역 간 **중첩이 불가**하다. 이로 인해:

- 권역 **경계선에서 발생하는 오더의 처리 문제**(물량 로스)가 상시 발생한다.
- "권역 내 모든 상점이 동일 공급권역으로 배송한다"는 전제가 B존 현장 운영과 맞지 않는다 (실제는 상점별 반경 N km 기준).
- 벤더별로 실제 운영 중인 **시간대별 원가**를 요일/시간대 할증으로 우회 구현하고 있어 설정이 복잡하고 정산 추적이 어렵다.
- 권역 밖으로 나간 기사의 **복귀(회귀) 오더** 개념이 없어 고밀도 지역 운영 효율이 떨어진다.

**결정 사항 (7/3 존/권역 분리 합의 → 7/7 풀스펙 진행 확정):**

- 영업기준(판가) 관리용 **존**과 벤더 배송(원가) 관리용 **권역**을 분리(디커플링)한다.
- 존은 중첩 불가(동일 위치 상점 = 동일 영업 조건), 권역은 중첩 허용(공급 음영 최소화).
- 원가는 **오더 생성 시점이 아닌 배차 시점**(수행 벤더 확정 시점)에 결정된다.
- 요금제 서버에서 원가 관리를 제거하고, 원가는 권역(벤더/라스트마일) 측에서 보유·관리한다.
- 최우선 구현 = **회귀 오더 처리 + 권역 외 할증** (리소스 조정 시에도 필수 구현).

> ⚠️ 용어: "존"(영업기준 단위, 구 빨간박스)과 "권역"(벤더 배송 단위, 구 파란박스)의 개념 구분까지만 합의됨. **정식 명칭(XX존, XX권역)은 미확정**이며 본 문서에서는 존 / 벤더 배송 권역으로 표기한다.

### 1.2 목표

- 존(판가)과 권역(원가)의 독립 운영 구조를 구축하여 권역 경계 물량 로스를 해소한다.
- 권역 중첩 허용 + 오더 3분류(권역 내/외/회귀) + AI 배차 연동으로 기사 공급 음영을 최소화한다.
- 벤더 운영 현실(요일/시간대별 원가, 상점 반경 기준 배송)을 시스템이 직접 지원한다.
- **목표 타임라인: 10월 말 ~ 11월 초·중순** (송파·강남 등 고밀도 지역 진출 전 완료 필수).

### 1.3 적용 대상

| 구분 | 대상 |
|------|------|
| **오더 유형** | 벤더 오더 (관제지점의 지점 타입이 벤더존인 오더). G4 + (선택적 스코프) G1 포함 |
| **시스템** | Vroong Intra(존 관리·ZONE 권역정책 관리·세트분배 관리·지도 시각화), 권역 서버, 벤더 관리 시스템, AI 배차, 라스트 마일, 요금제 서버, 정산 서버 |
| **사용자** | RM/BTF/사업기획(설정·운영), 벤더 소속 기사(배차·원가), G4 상점(판가 — 변동 없음) |

## 2. 성공 지표 (가안)

> 초기 PRD 수준의 가안. 수치 목표는 PRD 리뷰 및 베이스라인 측정 후 확정한다.

### 핵심 지표 (Core)
- 권역 경계 물량 로스(경계선 미배차·취소 오더) : **감소**
- 권역 외 오더·회귀 오더 수행률 : **신규 측정 → 목표 설정**
- 벤더 배송 권역 중첩 구간의 배차 성공률 : 단일 권역 구간과 **동등 수준**

### 보조 지표 (Usage)
- 회귀 오더 제안 → 수락률
- 시간대별 원가 설정 사용률 (할증 우회 설정 대비)
- 우선배차(honeymoon) 적용 상점의 초기 N회 오더 배송 품질 (SLA 준수율)

### 가드레일 지표 (Guardrail)
- 기존 G1~G3·A존 오더의 배차 성공률/정산 정합성 : **영향 없음**
- 벤더 정산 오차(원가 확정 시점 변경에 따른) : **증가 없음**
- 권역 GIS 연산 응답 성능 : 기존 수준 유지

## 3. 범위

### In-Scope (P0)

1. **판가 설정(존)** — 기존 구조 유지 + 존 역할을 판가 전용으로 정리
2. **원가 설정(ZONE 권역정책 관리 개편)** — 벤더 배송 권역 편집기(중첩 허용), 원가 요금제 탭, 원가할증 탭(권역 외 할증 신설)
3. **배차 방식 및 원가 산정** — 오더 3분류, 배차 시점 원가 확정, AI 배차 우선순위
4. **권역 시각화** — 지도 신규 메뉴 (존/권역 폴리곤, 호버·클릭)
5. **우선배차 설정(honeymoon, 가칭)** — 신규 상점 초기 오더 벤더 기사 우선 배차

### In-Scope (P1)

- 권역 시각화 — 폴리곤 호버 시 최근 1주 CM·CMR 표시

### 선택적 스코프 (리소스 협의)

- G1 벤더 오더 원가 일원화 (관제지점이 벤더존이면 G1 오더도 동일 원가 정책 적용)

### Out-of-Scope

- 관제지점 분리 (존 도입으로 관제지점 제거) — 영향도 커서 이번 스코프 제외 (7/7 합의)
- CM 예측 시스템 고도화 — 모니터링+하한선 검증 체계로 대체, 예측은 후속
- 프렌즈(파트너) 원가 산정식 확정 — 방향(베이스 원가 × 다이나믹 계수)만 유지, 상세는 별도
- 웹계약 시스템 개편 — 변경사항 싱크만 진행 (판가/존 구조는 불변)

## 6. 요건별 정책 및 기능

### 6.1 판가 설정 (존) — 기존 유지

> 존은 판가 관리 전용 컨테이너로 역할을 정리하며, 화면·정책 변경을 최소화한다.

| 정책 | 내용 |
|------|------|
| **권역 로드** | 기존과 동일하게 **지점에 설정한 권역을 불러오는 형태 유지**. 단, **세일즈 권역(지점의 픽업권역)만** 불러온다 |
| **중첩 정책** | 존의 세일즈 권역은 **다른 존과 중첩 불가** (기존 정책 유지) — 동일 위치 상점은 동일 영업 조건 |
| **거리별 판가** | 해당 존에 적용되는 거리별 판가 조건 설정 **기존과 동일 유지** |
| **할증** | 해당 존에 적용되는 할증 **기존과 동일 유지**. 단, 존 할증을 판가 전용으로 남길지는 **추가 논의 필요 (TBD-4)** |
| **적용 대상** | 해당 존에 연결된 지점 소속 **G4 상점은 오더 접수 시 모두 해당 판가/할증 조건을 자동 적용** |

### 6.2 원가 설정 (ZONE 권역정책 관리 개편)

> AS-IS: `ZONE 권역정책 관리`는 기본정보 / **적용 ZONE 선택(다른 정책과 중복 불가)** / 보상 조건·금액 / 세트 물량 구성 / 요일별 단위물량(5슬롯)으로 구성.
> TO-BE: 적용 ZONE 선택을 벤더 배송 권역으로 대체하고, 원가 관련 탭 2개를 신설한다.

**6.2.1 적용 벤더 배송 권역 (기존 `적용 ZONE 선택` 대체)**

- 권역 설정은 `ZONE 권역정책 관리` 내 **권역 편집기** 형태로 추가한다 (폴리곤 직접 편집).
- 다른 ZONE 권역정책의 `적용 벤더 배송 권역`과 **중복(중첩)되는 영역을 허용**한다.
  - (AS-IS의 "다른 정책에 저장된 ZONE 중복 연결 불가" 정책은 벤더 배송 권역에는 적용하지 않는다)

**6.2.2 `원가 요금제` 탭 (신설)**

상세 페이지 내 신설. 구성: `기본 거리` + `요일/시간대별 기본 원가` + `거리할증`

| 구성 요소 | 내용 |
|-----------|------|
| **기본 거리** | km 단위 거리 입력 필드. 아래 기본 원가가 적용되는 기준 거리 |
| **요일/시간대별 기본 원가** | 표 형태 입력 영역. **열 = 요일(7)**, **행 = 해당 권역정책의 요일별 단위물량에서 활성화된 시간슬롯(최대 5) + 시간 외 슬롯 1행**. 각 셀에 기본 거리에 적용할 원가를 입력 |
| **거리할증** | `추가 거리 단위`(km) + `추가 거리당 추가 원가` 입력. 기본 거리 초과분에 대해 단위 거리당 가산 |

**6.2.3 `원가할증` 탭 (신설)**

- 해당 탭에서 할증 목록을 **생성 혹은 선택** 가능하다. (적용 방식 — 기존 할증 생성 후 선택 vs 탭 내부 생성 — 은 **추가 논의 필요 (TBD-2)**)
- **권역 외 할증 타입 신설**: 권역 외 오더로 분류된 수행 건에 가산되는 할증.

**6.2.4 세트분배 관리 (기존 유지)**

- 기존과 같이 `세트분배 관리` 메뉴에서 해당 ZONE 권역정책에 연결될 **벤더 목록과 발주할 세트 수를 선택** 가능하다.

### 6.3 배차 방식 및 원가 산정

**6.3.1 오더 분류 (권역 기준, 벤더별 상대적)**

출발지/도착지 중 한 곳이라도 `벤더 배송 권역`에 들어갈 경우, 해당 권역이 적용된 ZONE 권역정책에 연결된 **벤더 소속 기사에게 제안·배차가 가능**하다.

| 분류 | 조건 (해당 벤더 배송 권역 기준) | 처리 |
|------|--------------------------------|------|
| **권역 내 오더** | 출발지·도착지 모두 권역 안 | 일반 제안 대상 |
| **권역 외 오더** | 출발지만 권역 안 | (지급 결정 시) 권역 외 할증 가산 |
| **회귀 오더** | 도착지만 권역 안 | 권역 밖 기사의 복귀 유도용 제안 |

- 같은 오더라도 기사가 속한 벤더가 속한 권역에 따라 분류와 원가가 달라질 수 있다.

**6.3.2 제안별 원가 산정**

- 배차 제안 시 **제안 대상 기사의 소속 벤더가 속한 권역의 원가 정책 + 적용 할증**에 따라 원가를 산정하여 **각각 제안**을 진행한다.
- 원가는 오더 생성 시점이 아닌 **배차(수행 주체 확정) 시점에 확정**된다.

**6.3.3 배차 제안 우선순위 (AI 배차)**

오더 배정 시 아래 사항을 추가로 고려하여 배차 제안을 진행한다.

1. **권역 내/외/회귀 여부**: 배송 퀄리티가 담보될 경우, **회귀 오더와 권역 내 배송 대상 기사를 우선 제안 대상**으로 고려한다.
2. **원가**: 배송 원가가 낮을수록 제안 우선순위를 높게 고려한다.
3. **회귀 오더 조건**: 기사가 **권역 경계 혹은 권역 외에 위치할 경우에만** 우선적으로 고려한다.

**6.3.4 기존 zone 요금제 원가와의 관계 (TBD-1)**

- 기존 zone 요금제의 원가 설정을 남겨놓고 할증으로 실제 원가에 맞춰 조정할지, 처음부터 `ZONE 권역정책 관리`의 원가 기준으로 정확히 판단할지 **결정 필요**.

| 항목 | 내용 |
|------|------|
| **메뉴 위치** | zone 요금제 설정 페이지 내 `우선배차 설정`(가칭) 메뉴 추가. **설정 위치는 추가 논의 필요 (TBD-3)** |
| **설정 항목** | ① 기능 사용/미사용 여부 ② 최초 N회 오더 입력 ③ and/or 조건 선택 ④ 최초 오더 발생 이후 N일 입력 |

- 조건 예: "최초 30회 오더 **and** 최초 오더 발생 후 14일" / "최초 30회 오더 **or** 최초 오더 발생 후 14일"
