## 30초 요약

**문제**: ZONE 하나가 판가와 원가를 동시에 소유하고, 영업·공급 권역이 한 몸으로 묶여 중첩이 불가하다.

**해결**: 두 축을 분리하고 **영업/공급 역할·메뉴를 나눈다.**

| 축 | 단위 | 구성 | 중첩 | 소유 |
|----|------|------|:----:|------|
| 영업(판가) | **영업존** | 지점 1 + 픽업지 권역 1 | 불가 | 판가 요금제, 판가 할증, 프로모션 |
| 공급(원가) | **배송권역 정책** + **원가 요금제** | 벤더 배송권역 N + 요금제 1 선택 | 허용 | 정책=매핑·단위물량·보상 / 요금제=기본원가·원가 할증 |

### 메뉴 트리

```
권역 관리
├ 영업존 관리
├ 벤더 배송권역 관리
└ 권역 시각화

요금 상품 관리
├ 판가 요금제 관리
├ 판가 할증 관리
├ 원가 요금제 관리
└ 원가 할증 관리

벤더 정책 관리
├ 배송권역 정책 관리
├ 세트 분배 관리
└ 벤더 관리
```

### 메뉴별 메인 검토 팀

인트라 메뉴 그룹 기준으로 **메인 리뷰 오너**를 나눈다. (교차 안건은 합동에서 다룸)

| 메뉴 그룹 | 포함 하위 메뉴 | 메인 검토 팀 |
|----------|----------------|-------------|
| **권역 관리** | 영업존 / 벤더 배송권역 / 권역 시각화 | **권역 서버** 담당 팀 |
| **요금 상품 관리** | 판가·원가 요금제 / 판가·원가 할증 | **핀테크** 팀 |
| **벤더 정책 관리** | 배송권역 정책 / 세트 분배 / 벤더 관리 | **벤더 서버 · 라스트마일** 담당 팀 |

> 트랙 매핑: 권역 관리 ≈ 트랙 A · 요금 상품 관리 ≈ 트랙 B · 벤더 정책 관리 ≈ 트랙 C. 배차·원가 런타임(트랙 D)은 메뉴 밖 서버/앱 영역으로 lastmile·dispatch가 메인.

### 역할

| 역할 | 담당 메뉴 |
|------|----------|
| **영업 담당자** | 영업존 / 판가 할증 / 판가 요금제 |
| **공급 담당자** | 벤더 배송권역 / 원가 할증 / 원가 요금제 / 배송권역 정책 / 세트분배 |

### 객체 연결

선후: **벤더 배송권역을 먼저 생성** → (1) 정책에 매핑 (2) 세트분배에서 벤더·세트 수.

| 규칙 | 내용 |
|------|------|
| 원가 요금제 | 정책당 **1개만** 선택. 요금제 1개 → 정책 N개 재사용 |
| 슬롯 | **양쪽 존재**. 정책=단위물량, 요금제=시간대 기본원가. **시간 구성 일치 불필요** |
| 원가 할증 | **원가 요금제에서만** 설정·선택 |
| 세트분배 | 축 = **벤더 배송권역** |
| 벤더 ↔ 정책 | 벤더는 **정책 1개에만** 속함 |
| 기사 후보 | 벤더 배송권역 → 연결된 정책 → 그 정책 소속 벤더의 기사 |
| 정책·벤더 변경 적용 | **그 이후 생성되는 오더부터** |
| 권역 외 할증 | **정액만** + **판가 미반영** |
| 상점 배송 접수 반경 | **기존 상점 설정 AS-IS** (영업존에 반경 필드 없음) |
