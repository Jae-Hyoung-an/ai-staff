**판가 요금제·판가 할증·원가 요금제·원가 할증 4종은 모두 목록 우선 진입**이다. 메뉴를 누르면 목록이 열리고, 행을 클릭하면 상세로 들어간다. AS-IS에서 판가 요금제·할증이 상세로 직행하던 동선을 통일한다.

**원가 요금제·원가 할증을 정책 탭이 아니라 독립 메뉴로 둔 이유**: 원가 요금제와 원가 할증(예: 기상 할증)은 여러 배송권역 정책에 공통으로 재사용된다. 정책 화면 안에서만 만들면 정책마다 중복 생성해야 한다. 생성·금액 관리는 `요금 상품 관리`에서, 정책과의 연결(선택)은 배송권역 정책 상세의 `원가 요금제 선택` 탭에서 한다.

## A. 권역 생성/관리

## S1. 영업존 관리 (목록)

메뉴: `권역 관리 > 영업존 관리`.

| 항목 | AS-IS | TO-BE |
|------|-------|-------|
| 메뉴·화면명 | 영업 관리 > ZONE 관리 | **권역 관리 > 영업존 관리** |
| 검색 조건 | ZONE 이름 | **영업존 이름** + **지점명**(추가) |
| 총 개수 표기 | `총 6개` | `총 6건` (타 화면과 통일) |

### 목록 테이블

| 컬럼 | AS-IS | TO-BE | 비고 |
|------|:-----:|:-----:|------|
| ID | ○ | ○ | |
| 영업존 이름 | ○ (ZONE 이름) | ○ | 라벨 변경 |
| 지점명 | ○ | ○ | 한 지점이 여러 영업존을 가질 수 있으므로 같은 지점이 여러 행에 나올 수 있다 |
| **픽업지 권역** | - | **신설** | 연결된 픽업지 권역명 1개 |
| **판가 요금제** | - | **신설** | 연결된 판가 요금제명. 미연결 시 `-` 강조 표시 |
| **지리 중첩** | - | **신설** | 다른 영업존의 픽업지 권역과 지리적으로 겹치면 `중첩` 오류 배지 (저장 차단) |
| 생성자 | ○ | ○ | |

> `판가 요금제` 컬럼을 넣는 이유: AS-IS에서는 판가 요금제 목록의 `대상 ZONE`이 실제 연결이 있어도 0으로 표시되는 결함이 있어, 운영자가 "이 존에 판가가 붙어 있는지"를 확인할 경로가 없다. 존 쪽에서 역방향으로 보여준다.

## S2. 영업존 상세 · 등록

메뉴: `권역 관리 > 영업존 관리` (목록에서 진입).

- 화면명: `영업존 상세` / **`영업존 등록`**
- 가능한 동작: `삭제` / `목록으로` / `저장`

### 섹션 1. 기본 정보

| 필드 | 필수 | AS-IS | TO-BE |
|------|:----:|-------|-------|
| 영업존 이름 | ● | ZONE 이름 | 라벨 변경 |
| 지점 | ● | `지점 ID` 라벨인데 지점명 표시 | 라벨을 **`지점`**으로 정정. 검색해서 선택 |

**안내문구**: `» 벤더존 운영방식의 지점만 매핑 가능합니다. 매핑 후에는 다른 지점으로 교체할 수 없습니다.`

- 지점은 **벤더존 운영방식 + 선택 가능한 픽업지 권역이 1개 이상 남은 지점**만 선택할 수 있다.
- 지점의 픽업지 권역이 모두 다른 영업존에 연결돼 있으면 선택 불가 + 이유 표시(`선택 가능한 픽업지 권역이 없습니다`).

### 섹션 2. 픽업지 권역 선택 ★ 신설

AS-IS의 `권역 정보`(세일즈 권역·공급 권역 읽기 전용 텍스트) 섹션을 대체한다.

| 요소 | 규격 |
|------|------|
| 안내문구 | `» 영업존은 지점의 픽업지 권역 1개로 구성됩니다. 이미 다른 영업존에 연결된 권역은 선택할 수 없습니다.` |
| 픽업지 권역 목록 | 지점이 보유한 픽업지 권역 중 **하나만 선택** (단일 선택). 각 행에 `픽업지 권역명` / `지역 수` / `연결 상태` 표시 |
| 연결 상태 | `선택 가능` / `{영업존명}에 연결됨` — 이미 연결된 권역은 선택 불가 처리 |
| 기본 선택 | 없음 (신규 등록 시 명시적으로 선택해야 한다) |
| 검증 | 미선택 시 저장 차단. 문구: `픽업지 권역을 선택해주세요.` |
| 지리 중첩 검증 | 선택한 권역이 **다른 영업존**의 픽업지 권역과 폴리곤이 겹치면 **저장 차단**. 같은 지점 채널 픽업지도 포함. 문구: `선택한 픽업지 권역이 {지점명}의 {권역명}(영업존: {영업존명})과 지리적으로 겹칩니다. 중첩을 해소한 뒤 저장해주세요.` |

**픽업지 권역 목록 예시 (성북 지점)**

| 선택 | 픽업지 권역명 | 지역 수 | 연결 상태 |
|:-:|--------------|--------|----------|
| ◉ | 성북 1 zone | 36 | 선택 가능 |
| ○ | YOGIYO_OD | 36 | 성북 1 (요기요OD)에 연결됨 |
| ○ | YOGIYO_DIRECT | 36 | 선택 가능 |

> **지리 중첩은 저장 불가**: 영업존 픽업지 권역끼리 폴리곤이 겹치면 신규 등록·권역 수정 모두 저장할 수 없다. 동일 지역을 덮는 채널별 픽업지(예: 성북 `YOGIYO_OD` / `YOGIYO_DIRECT`)는 권역을 분할하기 전에는 동시에 영업존으로 등록할 수 없다. 픽업지 권역 참조 중복 차단(5.1.3)과 지리 중첩 차단(5.1.4)을 함께 적용한다.

### 섹션 3. 지도 + 지역 목록

| 항목 | AS-IS | TO-BE |
|------|-------|-------|
| 표시 대상 | 세일즈 권역 + 픽업지 전체 + 배송지 | **선택한 픽업지 권역 1개만** |
| 범례 | `세일즈 권역` / `픽업지` / `배송지` 3종 | **`영업존 권역` 단일** |

| 미선택 시 | - | `픽업지 권역을 선택하면 지도에 표시됩니다.` 안내 표시 |
| 지역 목록 | `지역종류` / `픽업지명`(라벨 오류) | **`지역종류` / `지역명`**. 선택한 권역에 포함된 지역만 |
| 행정동/법정동 전환 | 제공 (기본 법정동) | 유지 |
| ~~배송 반경(판매권역) 오버레이~~ | 반경 원 표시 | **제거** — 지도에 판매권역/반경 오버레이를 그리지 않는다 |

### 섹션 4. ~~상점 배송 반경 설정~~ — v1.4 제거

> **v1.4 변경**: v1.3의 `상점 배송 반경 설정` 섹션과 `상점 판매권역` 관련 UI를 **영업존 화면에서 제거**한다.

| 항목 | 처리 |
|------|------|
| 상점 배송 접수 반경 | **기존 상점 설정을 그대로(AS-IS) 따른다.** 이번 개편에서 값·로직을 변경하지 않으며, 영업존 화면에서 입력·관리하지 않는다 |
| 상점 판매권역 섹션 | **삭제** (영업존은 픽업지 권역만 구성) |
| G4(직영센터) 상점 반경 | 상점 개별 설정 유지 — 영업존 단일값 관리로 옮기지 않는다 |

**안내문구**: `» 상점의 배송 접수 반경은 기존 상점 설정을 그대로 따릅니다. 영업존 개편으로 반경이 바뀌지 않습니다. 영업존은 픽업지 권역만 구성하며, 배송 반경/판매권역은 상점 화면에서 관리합니다.`

### 섹션 5. 이력 정보

AS-IS 없음 → **신설**. 형식은 배송권역 정책의 변경 이력 방식을 따른다.

## S7. 벤더 배송권역 관리 ★ 독립 메뉴

> **v1.4 변경**: v1.3에서 배송권역 정책 상세의 `벤더 배송권역` 탭이던 것을 **독립 메뉴**로 분리한다. 여기서 배송권역을 **생성**하고, 정책과의 연결(매핑)은 S6 탭 2에서 한다.

메뉴: `권역 관리 > 벤더 배송권역 관리`.

배송권역은 **지점 공급권역을 참조하는 방식으로만** 만든다. 폴리곤을 직접 그리거나 편집하는 기능은 제공하지 않는다.

### 목록 화면

| 컬럼 | 규격 |
|------|------|
| # | ○ |
| 배송권역명 | ○ |
| 연동 지점 | 참조 중인 지점명. 항상 값이 있다 (연동 없는 배송권역은 만들 수 없다) |
| 공급권역명 | 참조 중인 지점 공급권역명 |
| 면적(㎢) | ○ |
| 연결 정책 | 이 배송권역이 매핑된 배송권역 정책명. 없으면 `-` |
| 세트분배 벤더 수 | 세트 분배로 연결된 벤더 수 집계 |

- 행을 클릭하면 상세로, `배송권역 등록`으로 신규 등록 화면으로 들어간다.

| 항목 | 내용 |
|------|------|
| 선택 방법 | 지점명으로 검색 → 해당 지점의 공급권역 목록(`지점명` / `공급권역명` / `면적` / `이미 사용 중인 정책`)에서 선택 |

### 배송권역을 지점 공급권역으로 한정한 결과

| 항목 | 내용 |
|------|------|
| 권역 후보 집합 | 지점 공급권역으로 제한된다. 임의 폴리곤은 만들 수 없다 |
| 중첩이 성립하는 방식 | ① 한 정책이 여러 지점의 공급권역을 참조 ② 서로 다른 정책이 같은 공급권역을 참조 |

#### 섹션 3. 라이더비 (요일 × 시간대) — 시간대는 요금제 소유

| 필드 | 필수 | 규격 |
|------|:----:|------|
| 기본 거리 (km) | ● | 아래 라이더비가 적용되는 기준 거리 |
| 시간대 구성 | ● | **요금제 자체에서 정의**한다(배송권역 정책의 슬롯과 무관). 열 = 시간 구간(최대 5) + `시간 외` 1열 |

**라이더비 표**

- **행 = 요일 7개** (월~일)
- **열 = 요금제가 정의한 시간 구간(최대 5) + `시간 외` 1열**
- 열 머리에 시간 구간명과 시간 범위를 표시한다. 시간 구성은 **이 요금제에서 정의**하며 배송권역 정책 슬롯과 일치시킬 필요가 없다
- 각 칸에 해당 요일·시간대의 라이더비를 입력한다 (0 이상)
- 여러 칸을 선택해 같은 값을 한 번에 입력할 수 있다 (단위물량 표와 동일한 방식)

**예시 (요금제 시간 구간 기준)**

| 요일 | 아침<br>09:00~10:55 | 점심피크<br>10:55~14:00 | 점심논피크<br>14:00~16:55 | 저녁피크<br>16:55~20:00 | 저녁논피크<br>20:00~00:00 | **시간 외**<br>00:00~09:00 |
|------|------|------|------|------|------|------|
| 월 | 3,800 | 4,500 | 3,800 | 4,800 | 4,000 | 4,200 |
| … | | | | | | |

**`시간 외` 열 안내**: `» 요금제가 정의한 시간 구간이 덮지 않는 시간대(예: 00:00~09:00)에 적용됩니다.`

**슬롯 불일치 안내**: `» 배송권역 정책의 단위물량 슬롯과 시간 구성이 달라도 됩니다. 원가는 이 요금제의 시간 구간만 사용합니다.`

#### 섹션 4. 거리 할증

**적용 상한 거리 단일 필드는 두지 않는다.** 판가의 `거리별 요금`과 동일한 **구간 반복 방식**으로 입력하고, **마지막 구간의 끝이 최대 상한 거리**가 된다.

| 입력 항목 | 필수 | 규칙 |
|-----------|:----:|------|
| 구간 시작 (㎞) | ● | 직접 입력하지 않는다. 첫 행 = **기본 거리** 값, 2행 이후 = **직전 행의 구간 끝**을 자동 승계 |
| 구간 끝 (㎞) | ● | 직접 입력. 같은 행의 구간 시작보다 커야 한다 |
| 단위 거리 (㎞) | ● | 예: 0.1 |
| 단위당 원가 (VAT 미포함) | ● | 예: 230 |
| 행 추가·삭제 | | 구간을 자유롭게 추가·삭제할 수 있다 (최소 1행 유지) |

**예시 (기본 거리 1.5㎞)**

| 구간 시작 | 구간 끝 | 단위 거리 | 단위당 원가 |
|:---------:|:-------:|:---------:|------------:|
| 1.5 (고정) | 5 | 0.1 | 230원 |
| 5 (자동) | 10 | 0.1 | 300원 |
| 10 (자동) | 15 | 0.5 | 1,200원 |

**안내문구**: `» 마지막 구간의 끝(15㎞)이 거리 할증의 최대 상한입니다. 이를 초과하는 거리에는 추가 가산하지 않습니다.`

> 단일 구간 + 상한 필드로 단순화하려 했으나, 현행 원가·판가가 모두 다구간이라 **구간을 그대로 유지하는 것이 마이그레이션 무손실이고 판가 화면과도 일관**된다.

#### 섹션 5. 원가 요약

| 위치 | 내용 |
|------|------|
| 제목 | `원가 요약` |
| 설명 | `고정비 합계 + 라이더비(최고 시간대) + 거리 할증 전 구간 최대치의 VAT 포함 금액` |
| 내역 | `관제비 0원 + 관리비 150원 + 픽업비 0원 + 완료비 0원 + 라이더비 최고 4,800원 + 거리할증 최대 34,000원` |
| 합계 | `VAT 포함 최대 42,845원` |

**거리 할증 최대치 계산**: 각 구간의 `(구간 끝 − 구간 시작) ÷ 단위 거리 × 단위당 원가`를 전 구간 합산한다.

> AS-IS 요약식은 관제비·관리비를 빼고 합산하면서 문구는 "기본 요금 합계"라 오해를 유발했다. TO-BE는 항목을 전부 명시한다.

#### 섹션 6. 적용 원가 할증 선택 ★

판가 요금제의 `적용 판가 할증 선택`(S3 섹션 4)과 동일한 구조다.

| 항목 | 내용 |
|------|------|
| 안내문구 | `» 이 원가 요금제가 적용되는 정책의 오더에 가산될 원가 할증을 선택합니다. 복수 선택 가능합니다.` |
| 적용 목록 | `#` / `할증명` / `할증 종류` / `원가 금액` / `적용 기간` / `확정 시점` / `삭제` |
| 확정 시점 | `배차 시점` / `완료 시점`(기상 할증) — 예외를 목록에서 바로 볼 수 있게 노출한다 |
| 할증 추가 | 원가 할증 목록에서 검색해 선택한다 (S9에서 만든 할증) |
| 합산 표시 | `원가 할증 합계 (VAT 포함) N원` |
| 생성 경로 | 새 할증은 **`원가 할증 관리` 메뉴(S9)에서** 만든다. 이 섹션은 선택·해제만 담당한다 |

#### 섹션 7. 적용 배송권역 정책 (조회 전용)

이 원가 요금제를 선택한 배송권역 정책 목록을 **역참조**로 보여준다(읽기 위주). `정책명` / `배송권역 수` / `연결 벤더 수` / `정책 상세로 이동`.

### 검증 규칙

| # | 규칙 | 문구 |
|---|------|------|
| 1 | 라이더비 표 전 칸 입력 필수 | `입력되지 않은 시간대가 있습니다. ({요일}/{시간대})` |
| 2 | 기본 거리 > 0 | `기본 거리는 0보다 커야 합니다.` |
| 3 | 거리 할증 구간 1개 이상 | `거리 할증 구간을 최소 1개 입력해주세요.` |

> **v1.4 제거**: v1.3의 `활성 슬롯 변경 후 미입력 칸 존재` 검증은 삭제한다. 원가 요금제 시간대가 정책 슬롯과 독립이므로 **정책 슬롯 연동 검증이 없다.**

## S11. 세트분배 관리 (기준 축 = 벤더 배송권역)

메뉴: `벤더 정책 관리 > 세트 분배 관리`.

| 항목 | AS-IS | TO-BE |
|------|-------|-------|
| 기준 축 | ZONE | **벤더 배송권역** |
| 검색 조건 | `Zone 이름` | **`배송권역 정책명`** |
| 목록 컬럼 | `Zone 이름` / 연결 벤더 수 / 수행 세트 수 | **`배송권역 정책명`** / 연결 벤더 수 / 수행 세트 수 |
| 벤더 추가 | `해지` 상태 벤더도 선택 가능 | **해지·운영중지 벤더는 선택 불가**. **이미 다른 정책에 속한 벤더는 선택 불가** (벤더∈정책 1개) |

- **선후 관계**: 벤더 배송권역이 존재해야 세트 분배가 가능하다.
- **적용 시점**: 정책·벤더 연결 변경은 **그 이후 생성되는 오더부터** 반영. 이미 생성된 오더의 후보·원가는 바꾸지 않는다.

> 세트분배의 기준 축이 존 → 배송권역 정책(벤더 배송권역)으로 바뀐다. 기능·화면 구조는 그대로다. 해지·운영중지 벤더 선택 차단·**벤더 1정책 소속**은 AS-IS 결함 동반 수정·TBD-3 해소분.

## S14. ZONE 원가 요금제 메뉴 — 폐기 철회 · S8 재편

> **v1.4 변경**: v1.3에서 폐기 예정이던 AS-IS `G4 요금 상품 관리 > ZONE 원가 요금제 관리` 메뉴를 **폐기하지 않는다.** 원가 요금제를 정책 탭에 종속시키는 대신 **독립 메뉴(S8 `요금 상품 관리 > 원가 요금제 관리`)로 재편해 유지**한다.

| 항목 | 내용 |
|------|------|
| 대상 | AS-IS `ZONE 원가 요금제 관리` |
| 처리 | 메뉴를 **제거하지 않고 S8로 재편**한다. 원가 요금제는 정책이 선택하는 독립 자산이 된다 |
| 이관 | 기존 원가 요금제 5건(실운영 3건)을 S8 원가 요금제 목록으로 이관 + 검증 |
| 확인 필요 | 정산·리포트가 이 데이터를 직접 조회하는 경로 점검 (R2 마이그레이션 M5-a) |

> v1.3은 "원가 요금제가 배송권역 정책 소유"라는 전제로 메뉴를 폐기하려 했으나, v1.4에서 원가 요금제를 **재사용 가능한 독립 자산**으로 되돌리면서 메뉴를 살려 재편한다.

## So What

- **인트라 개발 핵심 화면**: **S7·S8 독립 메뉴화**, **S6 원가 입력 → 요금제 선택 전환**, **S9 적용 대상 = 원가 요금제**, **S11 축 = 벤더 배송권역**, **S2 배송 반경/판매권역 섹션 제거(상점 설정 AS-IS 유지)**.
