## 개요

노션 "벤더 신규 요구사항 목록"의 항목 중 **유저 시나리오(액터의 행동·화면·지표)에 영향을 주는 제품/정책 변경**만 정리했습니다. 순수 기술/안정성/보안/인증 연동 항목은 본 문서 및 PRD 본문 반영 대상에서 제외했습니다(별도 관리).

- **포함(유저 시나리오 영향)**: 거절률 산식, 권역 슬롯 운영, 시간대별 기록, 쿼터 이후 집계, 일간 기사 현황, 테이블 총개수 표시, 마스터 로그인
- **제외(기술/비-시나리오)**: 동시제안 로직(SD2-19), UAA 연동(SD2-30), 메시지 재시도 분류(SD2-27), 오퍼 중복 저장 멱등(SD2-38), VCC 재배정 이력(SD2-42), Plus App IDOR 차단(SD2-29), 정산 노이즈 알람(SD2-17), 실시간 출근수 버그(티켓無)

> ⚠️ **추론 표기**: 일부 티켓은 Jira 설명(description)이 비어 있어 **제목 기준으로 동작을 추론**했습니다. 표 내 "추론" 표기 항목은 담당자 확인이 필요합니다.

## 상세 변경 (AS-IS → TO-BE)

### 1. 거절률·수락전취소·수락후취소 정책 변경 (SD2-5, SD2-6)

| 구분 | 내용 |
|------|------|
| AS-IS | 거절건의 구성(수락 전/후 취소)과 거절률 산식이 명확히 정의되지 않아, 기사 배차 취소 후 상점 취소건이 잘못 반영되는 등 카운트 오류 발생 |
| TO-BE | 거절건을 수락 전 취소 + 수락 후 취소로 정의하고, 거절률 = 거절건 / 완료 오더로 산식 명문화. 벤더 기준/기사 기준 카운트 규칙 분리 |
| So What | 거절률 산식·카운트 규칙을 PRD에 명문화 → 벤더 평가/정산 신뢰성 확보 |

#### 산식

- **거절건 = 수락 전 취소건 + 수락 후 취소건**
- **거절률 = 거절건 / 완료 오더** (× 100, %)

#### 수락 전 취소건 — 벤더 기준

- 정의: 해당 벤더 소속 기사가 제안받은 오더를 수락하지 않은 건
- **단독(독점) 제안**: 적극 거절 + 만료(무응답) 거절 모두 포함
- **동시 제안**:
  - 제안 대상에 해당 벤더 소속 기사가 포함되고, 그 오더를 **아무도 수락하지 않았을 때** count
  - 누군가 수락했더라도, 해당 벤더 소속 기사가 **적극 거절**을 했으면 count
- **카운트 단위**: 오더 단위가 아닌 **제안 round 단위**. 동일 오더가 여러 거절건이 될 수 있음

#### 수락 전 취소건 — 기사 기준

- 거절한 기사마다 **각각** 누적
- 예: 같은 제안 round에서 벤더 소속 기사1·기사2가 한 오더를 제안받아 둘 다 거절 → 기사별 거절 count가 각각 추가됨
- 따라서 **기사 기준 거절건의 합 ≥ 벤더 기준 거절건** (클 수 있음)

#### 수락 후 취소건

- 해당 벤더 소속 기사가 오더 배차 이후 **Plus App에서 배차 취소**를 한 경우 count

### 2. 권역 슬롯 운영 — 슬롯 이름 변경 + 미사용 슬롯 (SD2-20, SD2-21)

| 구분 | 내용 |
|------|------|
| AS-IS | 요일별 단위물량 슬롯 이름 고정, 사용하지 않는 슬롯도 수락/거절률 집계에 포함됨 |
| TO-BE | 부릉 인트라 권역 관리에서 슬롯 이름을 변경 가능. 사용하지 않는 슬롯을 선택 가능하게 하고, 미사용 슬롯은 수락/거절률 산정에서 제외 |
| So What | 운영자가 슬롯을 직관적으로 식별하고, 미운영 시간대가 거절률을 왜곡하지 않도록 함 → 평가 공정성 향상 |

### 3. 시간대별 기록 개편 (SD2-34, SD2-39, SD2-40, SD2-41)

| 구분 | 내용 |
|------|------|
| AS-IS | 시간대별 기록에 불필요 슬롯 노출, 배정 건수 미표기, 취소건수 미표기, 완료 건수가 완료 시각 기준으로 귀속 |
| TO-BE | 불필요 슬롯 삭제(정리), 배정 건수 컬럼 추가(**순수 수락 수량** 기준), 취소건수 수량 컬럼 추가, 귀속은 **배정 완료 시간 기준**으로 변경 |
| So What | 시간대별 기록 표의 컬럼/귀속 기준을 일관되게 재정의 → 벤더포털·정산 지표의 정합성 확보 |

### 4. 쿼터 이후 물량 집계 (SD2-35)

| 구분 | 내용 |
|------|------|
| AS-IS | 세트 쿼터(목표)를 초과한 이후 수행 물량이 집계에서 누락 |
| TO-BE | 쿼터 초과 이후 물량도 집계에 포함 |
| So What | 실제 수행량이 지표에 온전히 반영 → 달성률/정산 누락 방지 |

### 5. 벤더포털 일간 기사 현황 화면 (SD2-31)

| 구분 | 내용 |
|------|------|
| AS-IS | 실시간/주간 위주 현황만 제공, 일 단위 기사별 현황 화면 부재 |
| TO-BE | 벤더포털에 일간 기사 현황 화면 신규 구현 |
| So What | VO가 일 단위로 기사 수행을 점검 가능 → 라이더 현황 메뉴에 일간 뷰 추가 |

### 6. 테이블 총 개수 표시 변경 (SD2-32)

| 구분 | 내용 |
|------|------|
| AS-IS | 벤더포털 테이블의 총 개수 표시가 현재 페이지 기준 등으로 부정확/혼동 |
| TO-BE | 총 개수를 전체 건수 기준으로 표기 |
| So What | 목록 규모 인지 정확도 향상 |

### 7. 마스터 로그인 (SD2-23)

| 구분 | 내용 |
|------|------|
| AS-IS | 벤더포털은 VO(Plus App 기사 계정) 기반 단일 인증만 제공, 운영/CS가 포털 상태를 점검할 수단 없음 |
| TO-BE | 벤더 AD 계정에 마스터 권한을 부여하여 마스터 로그인 지원 |
| So What | 운영/CS가 벤더포털을 직접 점검 가능 → 장애·문의 대응 속도 향상. 권한 범위(조회/조작)는 확인 필요 |
